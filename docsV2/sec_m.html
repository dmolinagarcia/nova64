Sheet 13 · M — Kernel–hardware interface
M

Kernel–hardware interface

Helium's control registers · command model · invariantsSHEET 13

Helium owns three pieces of state ordinary memory accesses cannot reach: the TLB, the active context, and the write-back cache. This sheet is the interface the kernel drives them through — and it sits strictly below the syscall layer. Source: fpga-a-control-registers.md.

  1. M.1
    Three layers, kept deliberately apart: the syscall ABI (COP, visible to processes) · the kernel's MMU and cache logic (C and assembly in bank $01, kernel only) · hardware control (stores to bank $FF, this sheet, kernel only). "Flush the TLB" and "flush a frame" must never become system calls: any process could then flush in a loop and degrade the whole machine — a trivial denial of service. They are steps inside munmap, inside the context switch, inside the page evictor. The command encodings therefore live in a numbering space entirely independent of the syscall numbers, and the two must never be aligned.
  2. M.2
    Address as opcode. Each command has its own address; the value written is the command's argument, not a command code — sta f:$FF0010 with an ASID in A flushes that ASID's TLB entries. Against the alternative of one command register plus a separate argument register, this removes the value decoder inside Helium (leaving the address comparator that already exists), removes the argument register, reduces every command to a single bus cycle, and kills a whole bug class: there is no intermediate "argument written, command not yet triggered" state for an interrupt to split.
  3. M.3
    Why memory-mapped and not WDM. An earlier proposal captured WDM ($42, reserved by WDC, executed as a two-byte two-cycle no-op) and had Helium decode its signature byte. Rejected on four counts: memory mapping widens a comparator that already exists for the fault registers, where a WDM snooper needs a new state machine tracking VPA/VDA to tell an opcode fetch from an operand; it inherits the protection keystone free, since $FF is already unmappable to user space, where WDM would need its own privilege gate; it is testable before a kernel exists, with the RP2040 driving the bus in E1–E3; and it keeps Argon honest — a softcore need only implement the documented instruction set, not replicate a private decode table. WDM stays a reserved no-op and Argon must implement it as one, decoding nothing. The single use it seemed to serve uniquely — a breakpoint insertable into user code, which cannot touch $FF — is already covered by BRK and its own vector.
  4. M.4
    The block lives at $FF:0000–$FF:00FF. All registers are 16 bits and are accessed with M=0; byte-granular access to one is undefined in this revision. Addresses not listed decode as no-ops on write and $00 on read.
  5. M.5
    Two completion classes, split by whether the command touches SDRAM. Synchronous — every TLB and context operation finishes within the bus cycle of the write (a flush is clearing validity bits in EBR, a context update is a register load), so there is nothing to poll and the effect is visible to the very next cycle. Asynchronous — the cache flushes, which may run for microseconds.
  6. M.6
    Asynchronous commands must not be implemented by stalling PHI2, even though a bounded hardware operation nominally qualifies (→ D16). Holding PHI2 low blocks interrupt service, which would inject microseconds of scheduler jitter on every page eviction. The kernel polls BUSY instead — the page evictor is already slow kernel code and the spin costs nothing there. Gateware rules: BUSY must read 1 on the first read after the triggering write, never lag — a kernel sampling a stale 0 would proceed against a half-flushed frame. A write to an async register while BUSY is set is ignored: it neither queues nor aborts. Ordinary CPU traffic keeps being served throughout, slowed but never stalled, and the timer and interrupts keep running.
  7. M.7
    Ordering comes free. The W65C816S has no prefetch queue and no store buffer: every bus cycle is architectural and appears in program order, so a store to a command register takes effect strictly after everything before it and strictly before everything after. No memory barrier is required, and none is provided. A PTE written to SRAM before a TLB_INVAL_PAGE is guaranteed visible to the walker at the moment of invalidation.
  8. M.8
    Two invariants the kernel must uphold, both of which fail silently. Write CTX_SET_PTBASE before CTX_SET_ASID: an interrupt taken between them then still sees the old ASID, whose TLB entries remain consistent with the old table. Reversed, the new ASID is live while the walker still reads the old table — filling the TLB with wrong entries tagged as correct. Flush an ASID before recycling it: skip that and the previous process's translations leak into a fresh address space, a total protection failure with no symptom until something is corrupted.
  9. M.9
    One requirement on the gateware, not an optimisation: the pinned region must be non-cacheable or write-through. Page tables live there and the walker reads SRAM directly, so if CPU writes to table memory went through the write-back cache the walker could read a stale PTE. The NC flag exists in the PTE format for exactly this (→ F.5).
