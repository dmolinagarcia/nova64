Sheet 12 · L — Virtual memory management
L

Virtual memory management

full paging · TLB · walker · stall vs ABORTSHEET 12

Every process sees a clean, contiguous 16 MB; Helium's MMU does the rest. The 65816's ABORTB pin turns this into real memory protection — but only for the faults that genuinely need the kernel; the frequent case never reaches software at all. Vocabulary and first-principles background in sheet K.

  1. L.1
    Virtual space: 16 MB per process (24-bit), full paging with 2 KB pages → 8,192 pages (13-bit page + 11-bit offset). Page size is decoupled from the 256 B fill granularity — they are two separate knobs. The tagged cache line, at 2 KB, does coincide with the page, and that coincidence is worth something (→ F.7).
  2. L.2
    Flat table: 8,192 PTEs × 32 bits = 32 KB per process. Active tables live in the 256 KB fixed region of SRAM (→ F.5), alongside the kernel, bank $00 and the vectors; inactive ones can live in the kernel's pageable memory. open How many tables stay resident once the kernel and bank $00 have taken their share is unresolved (→ Q9).
  3. L.3
    The SRAM never migrates a frame. Were a fill to move a page from an SDRAM frame into an SRAM frame, hardware would have to rewrite the PTE — which breaks mshare outright (a shared page has several PTEs, in different process tables, all pointing at the same frame; gateware cannot find and update them all) and leaves every other cached TLB entry holding a stale frame number. So the SRAM is a cache with tags, invisible to the page tables: the PTE always names the SDRAM frame and never changes.
  4. L.4
    Fault taxonomy — the distinction the gateware must enforce. Bounded: page resident in SDRAM but not in the SRAM cache → hardware fill with PHI2 stalled, µs range, no software involvement. Unbounded: page not present (zero-fill, swap from SD), permission violation, copy-on-write → ABORT to the kernel. Stalling PHI2 on a fault that needs the kernel deadlocks the machine instantly: the kernel is the only thing that could resolve it, and with the clock stopped it cannot run.
  5. L.5
    32-bit PTE (finalized format): FRAME[15:0] + P · W · X · U · D · A · NC · PIN + SW[7:0]. 27-bit physical address → 128 MB ceiling. Division of labour inside it: P, W, X, U and NC are checked by hardware; D and A are set by hardware — D by read-modify-write on the PTE in SRAM, A for the OS to read and clear when choosing swap victims; PIN and SW[7:0] are software-only and the walker ignores them. And one reuse worth knowing: when P=0 the whole FRAME field is free, since there is no frame to name — the OS stores the page's swap slot on the card there.
  6. L.6
    Physical frame map — the address space the FRAME field indexes is not all SDRAM. The 32,768 SDRAM frames sit at the bottom ($0000–$7FFF) and the 128 frames of the pinned SRAM region at the very top ($FF80–$FFFF), with everything between reserved for expansion. So "pinned" is a physical address range, not a cache line marked non-evictable: an access there bypasses tag lookup entirely and completes in one cycle at fixed latency (→ F.5).
  7. L.7
    TLB: 32–64 entries in EBR (the iCE40's 128 Kbit isn't enough for full on-chip tables), tagged by ASID → no flush on context switch. Reach: 64–128 KB of working set (→ K.4). Cache tags share the same EBR.
  8. L.8
    TLB miss → hardware walker, ≈100 ns: four SRAM accesses rather than two, since a 32-bit PTE is read eight bits at a time. Irrelevant against a 64-entry ASID-tagged TLB. Real faults → ABORTB with exact instruction retry; VPA validates X permission; VPB marks privilege transitions. Removing the frequent case from the ABORT path is a large de-risking: the 65816's ABORT has a deserved reputation for being delicate around instruction restart, and it is now exercised only where the process may be terminated anyway.
  9. L.9
    The kernel reads the fault in bank $FF registers: FAULT_ADDR · FAULT_CAUSE · CONTEXT · MODE.
  10. L.10
    Virtual bank map — architecture, not a proposal: $00 per-process stack + DP plus a minimal privileged zone (vectors, trampolines, kernel stack — a 65816 requirement: PBR=0 on interrupt entry) · $01 kernel · $02–$FD user · $FE VRAM window · $FF privileged I/O, not mappable to user space — the self-protecting key of the scheme. Everything downstream links inside $02–$FD (→ N.4); the boundaries do not move to accommodate a toolchain. Stated as a rule the gateware can check in eight bits: a user process may never hold DBR = $FF or PBR = $FF.
  11. L.11
    Bank $00 in practice — why the kernel cannot leave it wholly to the process. Two hardware facts force a kernel footprint there. Native-mode vectors sit at $00:FFE4–$FFEE and the CPU forces PBR=0 on entry, so every handler begins in bank $00: hence one or two privileged 2 KB pages holding the vectors plus short stubs that JSL into the real kernel in bank $01. And the interrupt frame is pushed onto the current stack before the kernel can intervene, which settles two things. The page S points into must be present unconditionally — an ABORT during interrupt entry would be a fault inside the fault mechanism, with no way back — so each process’s stack pages are pinned for its whole lifetime and never swapped. And the stub must switch S to a kernel stack, also inside those privileged pages, before doing any real work, so the kernel neither depends on the user stack nor leaks its own data back on return.
  12. L.12
    How privilege is acquired and lost — the piece that makes the rest enforceable. Entry to the kernel is always through COP (or an interrupt), which vectors to a known address, and the 65816 asserts VPB while fetching that vector. Helium takes VPB as the privilege transition: it raises privilege on the vector fetch and drops it again on the return to user code. The MODE register that holds this state lives in $FF and is therefore writable only while already privileged. That circularity is deliberate and is the whole scheme: were MODE reachable from user space, a process could simply grant itself permissions, and every other protection in this sheet would be decoration.
  13. L.13
    Physical allocator: frame bitmap over the SDRAM (32,768 × 2 KB). PIN marks non-evictable frames; NC marks uncached zones (I/O) — including the 256 KB fixed region, which is addressed directly and never cached.
  14. L.14
    ABORT handler: legitimate heap/stack growth → allocate a frame and retry; copy-on-write → duplicate and retry; anything else → kill the process. v1 uses eager loading; demand paging and swap to SD are post-v1.
  15. L.15
    Consequence for the kernel: once PHI2 can stop, cycle counts stop being time. The scheduler timer must be a free-running counter in Helium on its own clock, never derived from CPU cycles, and any delay loop written as a cycle count becomes invalid.
  16. L.16
    Swap-out rule, for when demand paging arrives: the cache sits in front of the SDRAM, so a frame written straight to the SD card would be the stale copy. Evict a page → flush the frame's dirty sub-blocks to SDRAM → only then write it to the card. Getting this order wrong corrupts silently, and only under memory pressure. The hardware side of it is F.7.
