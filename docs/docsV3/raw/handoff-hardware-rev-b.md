# DANI-65816 — Hardware Handoff (REV B)

**Date:** August 2026
**Scope:** Board-level architecture, memory hierarchy, pin budget, PTE format.
**Status:** Hardware frozen at block level. Ready for pin assignment and schematic capture.

---

## 1. Purpose of this document

This handoff captures the state of the DANI-65816 hardware design after the REV B
consolidation pass. It supersedes earlier notes where they conflict — in particular,
several components present in REV A have been **removed**, and the memory hierarchy has
been substantially simplified. Section 7 lists those removals explicitly so that no
obsolete part is carried forward into schematic capture.

The machine is an original portable computer built around the Western Design Center
W65C816S, a 16-bit CPU with a 24-bit address bus. It is not compatible with, and not
derived from, any existing 65816-based system. The design goal is a self-built portable
with virtual memory, memory protection, and a preemptive multitasking OS.

Two success milestones govern the project:

- **"Hito Apple II"** — the machine boots autonomously to a prompt.
- **"Hito Amiga"** — preemptive multitasking with a windowed GUI.

## 2. Global constraints

These constraints are non-negotiable and have driven most of the decisions below.

| Constraint | Consequence |
|---|---|
| All parts hand-solderable (TQFP / PLCC / TSOP, ≥0.5 mm pitch) | BGA packages excluded; iCE40 in TQ144 chosen over ECP5 in BGA256 |
| Single 3.3 V I/O rail | DDR3 excluded (1.35/1.5 V); SDR SDRAM and asynchronous SRAM retained |
| Fully open toolchain | Lattice iCE40 with Yosys / nextpnr / IceStorm |
| Portable form factor | Battery, charger, fuel gauge, integrated panel |

## 3. Board block architecture

```
   USB-C ──┬── MCP73871 (charge + power path) ── LiPo 1S ── MAX17048 (fuel gauge)
           │        │
           │        └── TPS63020 ── 3.3 V system rail ── LDO 1.2 V (3× FPGA cores)
           │
           └── RP2040 (embedded controller)
                 ├── config SPI ──────► FPGA-A, FPGA-B, FPGA-C
                 ├── SPI ─────────────► microSD (muxed with FPGA-A)
                 ├── PIO-USB host ────► USB-A (keyboard / mouse HID)
                 ├── I2C ─────────────► MAX17048, GT911 touch
                 └── USB-CDC ─────────► debug console

   W65C816S (PLCC-44 socket) ──┐
                               ├── shared 65816 bus ──► FPGA-A
   FPGA-C (softcore, optional)─┘

   FPGA-A (iCE40HX4K TQ144) — MMU, cache controller, peripherals
       ├── shared 16-bit parallel bus ──► SRAM 2 MB + SDRAM 32 MB
       └── VRAM_SEL / IRQ VSync ────────► FPGA-B

   FPGA-B (iCE40HX4K TQ144) — video and audio
       ├── local PSRAM 8 MB (chip RAM: framebuffer + audio buffers)
       ├── RGB-TTL ──► 10.1" 1024×600 panel (ER-TFT101-1, HX8282)
       └── I2S ─────► PCM5102A DAC
```

## 4. Component decisions

### 4.1 CPU

- **W65C816S in a PLCC-44 socket.** Socketed rather than soldered so the part can be
  swapped or removed during bring-up.
- **PHI2 is generated by FPGA-A**, not by an external oscillator. This allows clock
  stretching on cache miss, variable clock for power saving, and exact CPU/MMU
  synchronisation.
- **Bus arbitration via BE (Bus Enable).** Driving BE low tri-states the real CPU, which
  allows the optional softcore in FPGA-C to drive the *same* physical traces. No second
  footprint and no desoldering: the real CPU can remain in its socket permanently.
- The bank address (A16–A23) is multiplexed onto the data bus during PHI2 low and is
  latched **inside FPGA-A**. No external '573 latch is required.

### 4.2 FPGAs

Three iCE40HX4K devices in TQ144 packages. All three are configured by the RP2040 over
slave SPI at power-up.

| Device | Role | Populated |
|---|---|---|
| FPGA-A | MMU, cache controller, memory arbitration, peripherals | Always |
| FPGA-B | Video and audio | Always |
| FPGA-C | Softcore 65816 | Optional, unpopulated initially |

Moving the softcore out of FPGA-A into its own device returns block RAM and routing
resources to the memory subsystem, and lets the softcore's clock be optimised
independently of MMU timing.

**Known iCE40 limitation:** block RAM is approximately 16 KB per device. This is far too
small for flat page tables and is the direct cause of the memory layout in section 5.

### 4.3 Memory (FPGA-A)

| Part | Size | Interface | Role |
|---|---|---|---|
| IS61WV102416 | 2 MB | 16-bit async, 10 ns | Cache + page tables + pinned region |
| W9825G6KH | 32 MB | SDR SDRAM, 16-bit, 3.3 V | Main memory (physical frame pool) |
| microSD | — | SPI | Boot, filesystem, swap |

Both memories **share the same 16-bit parallel data bus and low address lines.** The
SDRAM requires only 7 additional control signals (CLK, CKE, CS, RAS, CAS, DQML, DQMH)
beyond what the SRAM already needs.

**Trade-off accepted:** because the bus is shared, a cache line fill serialises —
SDRAM burst into the FPGA, then FPGA out to SRAM, rather than overlapping. Miss latency
rises accordingly, but remains in the 200–300 ns range, far better than the QSPI PSRAM
path it replaced.

### 4.4 Video and audio (FPGA-B)

- **Panel:** ER-TFT101-1, 10.1", 1024×600 IPS, HX8282 controller, FPC-50, driven
  directly by RGB-TTL from the FPGA. Timing is generated natively; there is no scaler.
- **Pixel doubling:** the internal framebuffer is 512×300 and is doubled to 1024×600 on
  output. This keeps memory bandwidth within budget.
- **Local PSRAM (APS6404L, 8 MB)** serves as chip RAM for double-buffered framebuffer
  plus audio buffers. This is the one PSRAM that survives in the design — FPGA-B needs
  local memory with its own access path and cannot share FPGA-A's bus.
- **Bus topology is Amiga-style:** FPGA-B taps the CPU bus directly. The CPU writes VRAM
  through a 64 KB aperture at bank `$FE`, gated by a VRAM_SEL signal from the MMU. There
  is no dedicated inter-FPGA link.
- **Audio:** PCM5102A I2S DAC driven by FPGA-B. Backlight brightness is PWM from FPGA-B
  into a boost converter.
- **Touch:** GT911 capacitive controller on I2C, handled by the RP2040.

### 4.5 Embedded controller (RP2040)

The RP2040 fills the role of the small management microcontroller, and additionally
provides native USB. Responsibilities:

- Power sequencing and rail control; battery management via MAX17048 over I2C.
- Configuration of all three FPGAs over slave SPI (CRESET_B / CDONE handshake).
- BIOS preload: reads the BIOS image from microSD and writes it into system RAM before
  releasing CPU reset.
- USB-CDC debug console.
- USB HID host via PIO-USB, feeding keyboard and mouse events to FPGA-A.
- Its own firmware lives in a W25Q16 SPI flash and is updated over USB (UF2).

### 4.6 Power

```
USB-C ─► MCP73871 (charge + power path) ─► VSYS ─► TPS63020 buck-boost ─► 3.3 V
                                                       ├─► LDO 1.2 V (3× FPGA cores)
                                                       ├─► TPS61023 boost 5 V (USB VBUS)
                                                       └─► PT4110 boost (backlight)
LiPo 1S 3.7 V ── MAX17048 fuel gauge (I2C: state of charge, voltage, alerts)
```

The MCP73871 power-path topology allows the machine to run from USB with a fully
depleted battery. FPGA VPP (2.5 V) is derived through BAT54 diodes.

## 5. SRAM partitioning

The 2 MB SRAM is divided by address range in FPGA-A gateware. It is a single physical
chip; the partitioning exists only in the memory controller's decode logic.

| Range | Size | Contents |
|---|---|---|
| `$000000–$0FFFFF` | 1 MB | Cache: 4096 lines × 256 B |
| `$100000–$17FFFF` | 512 KB | Page tables: 16 contexts × 32 KB |
| `$180000–$1FFFFF` | 512 KB | Pinned region: kernel and per-process bank `$00` |

Three consequences worth carrying forward:

1. **The pinned region is a physical address range, not cache lines marked
   non-evictable.** Accesses to bank `$00` bypass tag lookup entirely and complete in a
   single cycle with fixed latency. This is both simpler and faster than the previous
   scheme.
2. **The hardware page-table walker becomes trivial.** With tables in 10 ns SRAM, a walk
   is one add and one read: `$100000 + context×32K + VPN×4`, two 16-bit accesses,
   roughly 4 cycles. A software TLB-miss trap is unnecessary; the OS only ever
   manipulates tables, never the TLB directly.
3. **Block RAM is freed for its proper use:** the TLB, cache tags (4096 tags fit in
   about 6 KB), and FIFOs.

## 6. Page table entry format

```
 31                            16 15 14 13 12 11 10  9  8  7        0
┌────────────────────────────────┬──┬──┬──┬──┬──┬──┬──┬──┬──────────┐
│         FRAME[15:0]            │P │W │X │U │D │A │NC│PIN│ SW[7:0] │
└────────────────────────────────┴──┴──┴──┴──┴──┴──┴──┴──┴──────────┘
```

Page size is 2 KB, giving 8192 pages per process and a **32 KB flat page table per
process** (8192 entries × 4 bytes). Sixteen contexts therefore occupy exactly the 512 KB
table region defined in section 5.

Note that this supersedes an earlier estimate of ~16 KB per table, which assumed 2-byte
entries. The 32-bit PTE is what makes the 16-bit frame field — and the 128 MB ceiling —
possible.

**FRAME[15:0]** — physical frame number. Physical address = FRAME × 2048 + offset(11
bits) = 27 bits, giving a **128 MB physical ceiling**. Current frame map:

- `$0000–$3FFF` — SDRAM, 32 MB
- `$FF00–$FFFF` — the 512 KB pinned SRAM region (256 frames)
- Intermediate range reserved for future expansion

**Hardware-checked flags:**

| Bit | Name | Behaviour |
|---|---|---|
| P | Present | P=0 on any access → ABORT. When P=0, bits 31–16 are free for the OS to store the swap slot on SD |
| W | Writable | Write with W=0 → ABORT. Also provides copy-on-write |
| X | Executable | Fetch with X=0 → ABORT. The 65816 **VPA** signal identifies instruction fetch cycles, so the check is a simple AND |
| U | User-accessible | User-mode access with U=0 → ABORT |
| D | Dirty | Set by hardware via read-modify-write to the PTE in SRAM |
| A | Accessed | Set by hardware; OS reads and clears to select swap victims |
| NC | Non-cacheable | Frame bypasses the cache |

**Software-only bits:** PIN (do not evict — ignored by the walker) and SW[7:0], free for
the OS (age counter for replacement, COW marker, and so on).

**Privilege mode.** The 65816 has no privilege bit, but it does assert **VPB** (vector
pull) when reading an interrupt or COP vector. The MMU uses VPB to switch to supervisor
mode automatically. Returning to user mode is a write to a register in bank `$FF`, which
is itself only writable in supervisor mode — the self-protecting keystone of the
protection scheme.

**TLB entry:** `VPN(13) + ASID(4) + FRAME(16) + W, X, U, NC` ≈ 37 bits. Including the
ASID (the context number) avoids flushing the TLB on every context switch; switching
processes remains a single register write with no collateral cost. 64–128 entries in
block RAM are sufficient for a 65816 working set.

**Fault registers in bank `$FF`** required by the ABORT handler:

- `FAULT_ADDR` — faulting virtual address, 24 bits
- `FAULT_CAUSE` — ¬P / ¬W / ¬X / ¬U, plus a fetch/data bit
- `CONTEXT` — active ASID
- `MODE` — supervisor/user, writable only in supervisor mode

## 7. Removed from the design

These parts appeared in earlier revisions and must **not** be carried into schematic
capture.

| Removed | Reason |
|---|---|
| ECP5 FPGAs (BGA256) | Not hand-solderable; replaced by iCE40 TQ144 |
| Dedicated page-table SRAM | Needs ~35 pins; impossible in TQ144. Tables moved into the main 2 MB SRAM |
| 2× APS6404L PSRAM on FPGA-A | Superseded by SDRAM. Frees 12 pins and removes the QSPI controller — the most timing-sensitive gateware block in the design |
| W25Q128 BIOS flash | Pin budget conflict with SDRAM. Boot is SD-only; the RP2040's own flash is the silicon fallback |
| ANX6345 eDP bridge | Panel is driven directly by RGB-TTL. Deferred to a later build stage |
| VGA output and R-2R DAC | Integrated panel is the primary display |
| 8×8 keyboard matrix | Replaced by USB HID via the RP2040's PIO-USB host |
| HDMI/DVI output | Deferred; differential pairs may be routed but not populated |

## 8. Pin budget — FPGA-A (iCE40HX4K TQ144)

107 usable I/O. CRESET_B and CDONE are separate; the four config SPI pins are
dual-purpose and reusable after configuration.

| Group | Signals | Pins |
|---|---|---|
| 65816 bus | D/BA0-7, A0-15, PHI2, RWB, VDA, VPA, RDY, ABORTB, IRQB, NMIB, RESB, BE, E | 35 |
| SRAM 2 MB | A0-19, D0-15, OE, WE, UB, LB (CE tied low) | 40 |
| SDRAM (incremental) | CLK, CKE, CS, RAS, CAS, DQML, DQMH — data and low address shared with SRAM | 7 |
| microSD | SPI ×4 (mux select driven by RP2040) | 4 |
| I2C | SDA, SCL | 2 |
| RP2040 link | config SPI reused post-config, plus UART | 2 |
| Inter-FPGA | VRAM_SEL, IRQ VSync, handshake | 3 |
| **Total used** | | **93** |
| **Free** | | **14** |

Suggested use of spares: activity LED, debug test points. During bring-up these are
worth more than any additional peripheral.

## 9. Layout notes

- SRAM and SDRAM must be placed physically adjacent and close to FPGA-A. The shared bus
  runs at approximately 100 MHz toward the SDRAM and will not tolerate long stubs.
- Data and address lines should be routed as a short comb between the two memories.
- 4-layer stackup (signal / GND / 3V3 / signal).
- JTAG accessible on each FPGA, or chained.
- Populate the first board in stages: power → RP2040 → FPGA-A → CPU → memories → FPGA-B.

## 10. Open items

**Immediate design decisions:**

- Context switch implementation: saving and restoring full CPU state, and notifying
  FPGA-A of the active process change to swap permission tables.
- Hardware watchdog converting a hung fill into NMI or ABORT.
- SDRAM auto-refresh interleaving during cache line fills.
- Glitch-free PHI2 gating, with correct minimum pulse widths on restart.
- BE arbitration protocol: who initiates the handover, what happens to PHI2 and RDY
  during the switch, and whether FPGA-C may run at its own higher clock against the same
  MMU.

**Blocking KiCad work:**

- ER-TFT101-1 datasheet needed for backlight current and voltage, and to confirm the
  capacitive touch variant. The panel must be ordered in the capacitive variant.

**Next documents to produce:**

- Physical pin assignment for FPGA-A TQ144, ensuring the SRAM/SDRAM bus falls in
  contiguous banks and the panel interface is grouped on FPGA-B.
- Kernel ABORT handler state machine: classify via FAULT_CAUSE, decide between allocate
  frame / fetch from swap / kill process, and return via RTI.
