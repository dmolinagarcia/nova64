# Process management
> PCB · context switch · scheduler · binary format

The piece that turns the machine into "an Amiga": several isolated processes taking turns without knowing it, with the MMU eliminating relocation at the root.

- N.1 — PCB per process: registers (A · X · Y · S · D · DBR · PBR · P · PC), ASID, pointer to its page table, state, and queues. [[open]]
  NOTE: The save set is not ours to choose: it must cover exactly what the C compiler treats as live state, direct-page pseudo-registers included. That audit has not been done (→ [Q19](sec_ai_q#q19)).
  NOTE: **Much of that set may not need saving at all.** Calypsi's pseudo-registers live in the direct page, and the direct page is in the process's own virtual bank `$00` ([N.4](sec_ai_n#n4)), so a switch that changes the page table leaves each process's pseudo-registers where they were — provided the kernel's entry stub moves D to a direct page of its own before any C runs, as it must for the reason [L.11](sec_ai_l#l11) gives for S. The audit then has to find only the state Calypsi keeps outside the direct page. It is the arrangement 65816-OS is built on, a direct page per task (DN-SW-EMU-004), obtained here from the MMU instead of from a fixed carve-up of bank `$00`.
- N.2 — Context switch: save state to the PCB → write CONTEXT/ASID to the MMU → restore the next one. Tens of µs; no TLB flush thanks to ASID.
  NOTE: Order matters and is not optional: write `CTX_SET_PTBASE` before `CTX_SET_ASID`, or an interrupt landing between the two leaves the new ASID live while the walker still reads the old table (→ [M.8](sec_ai_m#m8)). The bank `$00` question that used to block this is settled in [L.11](sec_ai_l#l11); only sizing remains (→ [Q18](sec_ai_q#q18)).
  NOTE: **Where the saved registers live is a choice, and the prior art shows its costly side.** 65816-OS copies every register out of the interrupt frame into its task table and writes the next task's values back into a rebuilt frame, and its recorded interrupt bugs cluster on that path (DN-SW-EMU-004). The cheaper form leaves the frame where the interrupt pushed it — on the process's own pinned stack ([L.11](sec_ai_l#l11)) — and keeps S in the PCB: store S, the two MMU writes in the order above, load the next S, and the common exit sequence. Whether that suits one shared kernel stack or needs one per process is [Q18](sec_ai_q#q18)'s sizing question.
- N.3 — Scheduler: preemptive round-robin with a 100 Hz timer tick; per-device blocked queues; 2–3 priority levels as a later option. `sleep()` is backed by Helium's free-running counter, never by cycle counting (→ [L.15](sec_ai_l#l15)).
- N.4 — One canonical virtual layout, identical for every process: stack and direct page in virtual bank `$00` (a hardware requirement of the 65816), then crt0 and `.text` from `$02:0000`, then `.data`, then `.bss`, then a heap growing upward — `sbrk` merely moves a pointer and the frames arrive lazily by ABORT.
  NOTE: User code starts at `$02`, not `$01`: the bank map of [L.10](sec_ai_l#l10) is architecture and does not move for the loader. Region addresses within `$02–$EF`, stack size and heap start are still to be frozen (→ [Q17](sec_ai_q#q17)).
  NOTE: **Two things are reserved in that layout from the first loader, not from the first VM** ([D91](sec_ai_q#d91)). Banks `$00`–`$01` stay unmappable by a guest segment — `$00` for the 65816 direct pages and stack, `$01` for the interpreter and its dispatch table when it arrives — and **the last 2 KB page of bank `$00` is a shared read-only page holding the system information block**, written by the BIOS before paging is enabled and mapped identically into every process ([VM2.29](sec_ai_vm2#vm229), [L.11](sec_ai_l#l11)). Both cost nothing today. **Reclaiming that region once processes exist is a migration, not an edit**, which is the whole argument for doing it here.
- N.5 — Custom binary format: header (magic, entry point) + segments with vaddr · filesz · memsz · R/W/X permissions matching the PTE bits. `.bss` occupies no bytes on disk, only a size in the header.
  NOTE: Field layout, magic value and versioning still to be specified (→ [Q20](sec_ai_q#q20)).
  NOTE: **NVX is a second format beside this one, not a replacement for it** ([VM1.41](sec_ai_vm1#vm141)). It carries the same premise — fixed virtual addresses, no relocation, permissions per section — and adds an ISA version and a feature-bit vector, because one NVX image must run on three executors and the loader has to be able to refuse one it cannot ([VM1.43](sec_ai_vm1#vm143)). **Whatever is frozen for the native header should be frozen knowing a sibling exists**, or the two diverge for no reason.
- N.6 — Loading (`exec`): create the page table, copy segments from the card into frames and map them with their permissions, zero `.bss`, map the stack, place the arguments where crt0 expects them, and `RTI` into the entry point **in user mode**. From there crt0 finishes initialisation, calls `main()`, and issues `exit()` when it returns. Every process sees the same addresses: the MMU makes relocation unnecessary.
- N.7 — Lifecycle: exec → ready → running ⇄ blocked → zombie → wait. Isolation is demonstrated in E7: one process dies and the other keeps running.
