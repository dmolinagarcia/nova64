# Peripherals and their location
> which chip · who it hangs off · how the OS sees it

Every peripheral has a clear physical owner and a uniform interface toward software: a `/dev/*` node served by a kernel driver.

| Peripheral | Chip / interface | Hangs off | Access from the OS |
|---|---|---|---|
| 10.1” 1024×600 panel | ER-TFT101-1 · HX8282 · RGB-TTL FPC-50 · 18 bpp · 51.5625 MHz → 59.95 Hz ([T.5](sec_ai_t#t5)). **The 60 Hz is physics, not preference**: TFT pixels are capacitors that need refreshing, and polarity inversion becomes visible flicker as the rate drops — 30 Hz is out of spec and ~50 Hz buys only ~17% for a worse image | Neon (FPGA-B) | `/dev/fb` — VRAM mapping via ioctl, **for asset upload, not per-pixel drawing** ([J.5](sec_ai_j#j5)) |
| Screen console | Mode 0 · 128 × 32 cells of 8 × 16 px, text buffer and font in Neon's block RAM, both initialised from the bitstream — **it displays before any software exists** ([T.53](sec_ai_t#t53)) | Neon (FPGA-B) | `/dev/con` — the kernel's own console, distinct from the serial `/dev/tty` below (→ [Q47](sec_ai_q#q47)) |
| Video modes | 0 text · 1 hires mono 1024×600 at 1 bpp, the GUI mode · 2a 320×200 and 2b 512×300 at 8 bpp with a 256-entry palette, both replicated to the panel. **Px-doubling is Mode 2b, not a property of the machine** ([T.33](sec_ai_t#t33)) | Neon (FPGA-B) | `ioctl` on `/dev/fb`; drawing goes through the command channel, never through the CPU |
| Drawing engine | Blitter — fill, copy, keyed copy, tiled copy, 1-bpp expand, lines — plus a command processor executing display lists out of Neon's SDRAM with no CPU involvement ([sheet T](sec_ai_t)) | Neon (FPGA-B) | commands written to `CMD_PORT`, or a list the kernel builds once and patches |
| VGA (bring-up) | R-2R ladders hung off the top bits of the panel's own RGB bus through isolating jumpers — so it costs only 2 dedicated sync pins · 640×480 / 800×600. Its pixel clock does not fall out of the video domain and wants Neon's free second PLL (→ [Q54](sec_ai_q#q54)) | Neon (FPGA-B) | same framebuffer, same timing generator with different parameters |
| Capacitive touch | GT911 · I2C + INT (module's capacitive variant) | **I2C-SW**, the switched-domain bus — its pull-ups would back-feed a dead rail on the always-on one ([C.13](sec_ai_c#c13)) | `/dev/touch` |
| Audio | **Fully specified in [sheet W](sec_ai_w)** — four channels, a hardware mixer, and a sample rate of 44,146 Hz because no PLL setting on this board reaches 44,100 ([W.11](sec_ai_w#w11)). PCM5102A · I2S · DMA buffers in Neon's SDRAM. Strapped `FLT`/`DEMP`/`FMT` low, `SCK` to GND for the part's internal PLL, and `XSMT` to 3V3 through an RC — that delay is the anti-pop, and without it every power-up is a click in the headphones | Neon (FPGA-B) | `/dev/audio` |
| Keyboard / mouse | USB HID · native host controller + on-board hub IC · switched VBUS per port ([D1.10](sec_ai_d1#d110)) | RP2354B → EC channel | `/dev/kbd` · `/dev/mouse` |
| Serial console | UART ↔ the EC's `J-DBG` UART ([D1.4](sec_ai_d1#d14)) | Helium ↔ RP2354B | `/dev/tty` |
| Storage | microSD · SPI · '3257 mux · a register block in bank `$FF` with a FIFO path and a DMA path, the latter depositing blocks straight into SDRAM ([G.6](sec_ai_g#g6), [D45](sec_ai_q#d45)) | Helium (FPGA-A) | `/dev/sd` → FS |
| Real-time clock | PCF8563 · I2C | **Unassigned since the bus split**; it wants to keep time while the machine is off. `I2C-EXP` is the third answer, with a backup cell doing what no bus can ([H.5](sec_ai_h#h5), [X.22](sec_ai_x#x22), [Q35](sec_ai_q#q35)) | `/dev/rtc` |
| Battery and power | MAX17048 + BQ25896 · I2C-AON, EC-owned | RP2354B → telemetry snapshot in Helium → bank `$FF` ([sheet S](sec_ai_s)) | `/dev/power` — latch, then read; `ioctl` for poweroff and reboot |
| Power button | Momentary, wired to both `QON` and an AON GPIO | RP2354B (duration) and BQ25896 (hardware floor) | Arrives as an interrupt and a `/dev/power` state, not as a key event |
| Timer + interrupts | 100 Hz timer · prioritized PIC · IRQ/NMI/ABORT | Helium (FPGA-A) | scheduler tick |
| VSync, raster and `SIGNAL` | One IRQ line, three sources, demultiplexed by the kernel reading `IRQ_STATUS` ([T.47](sec_ai_t#t47)) | Neon → PIC | GUI sync, raster effects, and the display list telling the CPU a frame is safe to patch |
| Backlight | PT4110 boost · `EN` and PWM. **Owned by the EC, not Neon** — the only party awake before Neon is configured and while the switched domain comes down ([T.52](sec_ai_t#t52)) | RP2354B GPIO ([D1.6](sec_ai_d1#d16)) | brightness through `/dev/power`, not `/dev/fb` |
| Expansion slot | Shared bus: a 256-byte register window in `$FF`, a 1 MB aperture the MMU can map, and the three nets of [X.2](sec_ai_x#x2). **Unpopulated in build 1** — three Helium pins and a connector ([sheet X](sec_ai_x)) | Helium (FPGA-A) | whatever the card is; the slot itself has no node |
| Slow bus — `I2C-EXP` | Third I2C bus, Helium its only master, devices **mirrored into I/O windows** by a sequencer — a byte is ~90 µs and nothing may stall PHI2 for that ([X.23](sec_ai_x#x23)). Two pins already budgeted | Helium (FPGA-A) | per device — the PCF8563 above is its first candidate tenant |

## The rules the table encodes — one owner, one node, and a bus chosen by domain rather than by convenience.

- H.1 — **One owner per peripheral, and the third column says which.** Every row names exactly one device that drives the part — Neon, Helium or the RP2354B — and nothing on this board answers to two masters at once. Where two parties need the same device it is **handed over, not shared**: the microSD passes from the RP2354B to Helium through the '3257 mux, one owner at a time.
- H.2 — **One face toward software.** Everything software touches is a `/dev/*` node behind [J.4](sec_ai_j#j4)'s five-function driver interface, and the table's two exceptions are deliberate. The power button arrives as an interrupt and a `/dev/power` state, not a key event, because it must work with no process listening; and the slot has no node of its own, because what it is depends on the card ([sheet X](sec_ai_x)). NOTE: `/dev/con` is the panel, `/dev/tty` the serial line (→ [Q47](sec_ai_q#q47)).
- H.3 — **Which I2C bus a device sits on is a power-domain decision, not a convenience one** ([C.13](sec_ai_c#c13)). `I2C-AON` carries the charger and the gauge and nothing else, because anything on it must be safe to leave powered whenever SYS exists. `I2C-SW` carries the touch controller, whose pull-ups would back-feed a dead rail from the always-on side. `I2C-EXP` is Helium's own, and its devices are mirrored into windows rather than reached transactionally ([X.22](sec_ai_x#x22)).
- H.4 — **The three owners divide by deadline.** Neon takes what has a hard per-frame deadline — pixels, the display list, the audio DMA — the only device with local memory and nothing in front of it. Helium takes what lives in the memory path — storage, the timer, the PIC — a request answered inside a bus cycle cannot cross a link first. The EC takes what must be awake when the machine is not: power, the backlight, USB HID long before a kernel exists.
  NOTE: Nothing in the table hangs off Argon: an unpopulated device owns no peripheral.
- H.5 — **Two rows are still open, and both are placement questions, not design ones.** The **RTC** has no bus: it wants to keep time while the machine is off, which argues the always-on side, against a bus reserved to charger and gauge — and [X.22](sec_ai_x#x22) now offers a third answer (→ [Q35](sec_ai_q#q35)). The **VGA output** has no clock: its pixel rate does not fall out of the video domain, and it is now the only claimant on Neon's free second PLL, [W.11](sec_ai_w#w11) having removed audio's (→ [Q54](sec_ai_q#q54)).
  NOTE: Neither is on the path to a milestone, which is why both have stayed open.
- H.6 — **The table is the whole of the board's I/O.** A device that is not in it is not fitted, and adding one is not a soldering job: it needs an owner, a bus that suits its power domain, a node and a driver — or, if it is slow and trivial, the tier of [X.21](sec_ai_x#x21). The two deliberate blanks are in the table: the slot, unpopulated in the first build, and an `I2C-EXP` with no tenant assigned yet.
