# Global architecture
> physical CPU + optional softcore · Helium = northbridge · Neon = video/audio

An Amiga-style shared bus with four inhabitants: the physical CPU, two always-present FPGAs — Helium (FPGA-A) and Neon (FPGA-B) — and an optional third, Argon (FPGA-C). The RP2040 stays off the bus, acting as the board controller.

- B.1 — CPU: W65C816S in a PLCC-44 socket, 24-bit native mode. PHI2 generated by FPGA-A (Helium), target 8 MHz at 3.3V. The BE signal lets the CPU release the bus — used both by Argon and, far more often, by Helium itself to take the shared nets during a fill (→ [F.4](sec_f#f4)). Detail in [sheet E](sec_e).
- B.2 — FPGA-A (Helium) — the "northbridge": MMU + TLB + walker, cache, bus arbiter, prioritized interrupt controller, system timer, UART, SPI-SD, I2C, and CPU glue logic. **A pure state machine**, never a soft CPU: anything in the critical memory path pays for itself on every access. Intelligence — filesystems, protocol stacks — lives in the RP2040 or in 65816 software.
  NOTE: iCE40HX8K TQ144 · budget: 90/107 pins for CPU bus + SDRAM + SRAM, 17 free. [[open]] the free pins do not yet cover SPI-SD, UART and the debug port (→ [Q8](sec_q#q8)).
- B.3 — FPGA-B (Neon) — video and audio: taps the bus directly; the CPU writes to it through a 64 KB VRAM window in bank `$FE`, validated by the MMU's VRAM_SEL signal. Its own 64 MB SDRAM (chip RAM — same part and same controller as Helium's), RGB-TTL output to the panel, bring-up VGA, and PCM5102A over I2S.
  NOTE: Local memory rather than streaming pixels from Helium: video across a link would need ~26 MB/s sustained with hard deadlines and would make Helium the bottleneck for the whole machine.
- B.4 — FPGA-C (Argon) — optional, unpopulated at first: a 65816 softcore (P65816 reference) that takes the same bus with BE=0. Allows switching from the real CPU to a softcore without touching the rest.
  NOTE: Whether that is worth doing is a live question — on this platform the win is CPI and features, not clock (→ [sheet E](sec_e), [Q13](sec_q#q13)).
- B.5 — RP2040 — embedded controller off the bus: configures, boots, and watches over the system (→ sheet D). The board's only mandatory flash: its W25Q16.
- B.6 — Interconnect: a single shared A/D/control bus. The dedicated *data* link between FPGAs was removed, but two control lines survive it — **VRAM_SEL** (Helium → Neon, asserted only after translation and the permission check, which is what keeps protection intact) and **BWAIT** (Neon → Helium, stretching RDY on VRAM reads). The microSD is shared between the RP2040 and Helium via a '3257 mux (→ sheet G).
- B.7 — Clocking: **one 25 MHz oscillator** in a star to the three FPGAs, entering each through a GBIN pin; every device's PLL then synthesises what it needs — Helium's core and PHI2, Neon's pixel clock, Argon's core. One part, one net, and no cross-chip skew to reason about.
- B.8 — Safe state with no bitstream loaded: **RESB pulled down** so the CPU stays in reset, control lines pulled up so nothing reads as asserted, and the shared data bus held by weak pull-ups so it never floats.
  NOTE: The board can be powered with all three FPGAs blank and nothing fights for the bus — which is exactly what makes the staged bring-up of [E1.5–E1.7](sec_p) possible.
