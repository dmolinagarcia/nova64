# Debug agent and console
> a requester inside Helium · link-only control · the console that drives it

Instrumentation, not a product feature. A hardware block inside Helium performs memory and bus accesses on command, and a text monitor on the RP2354B drives it — so the board is observable from the first stage at which anything can be powered, long before a BIOS or a kernel exists. It is expected to stay in the design permanently, gated off rather than removed. **Since REV C it is also boot-critical: `bios.bin` reaches SRAM through this block and no other** ([R.25](sec_ai_r#r25)).

- R.1 — Five capabilities define it, and everything else on this sheet is their cost: read and write **any physical location** (SRAM and SDRAM), read and write **through the MMU** once translation exists, generate **real bus cycles** other devices can see, **halt · single-step · trace** the W65C816S, and do all of it from a terminal over the EC's console UART ([R.19](sec_ai_r#r19)).
  NOTE: **The five arrive in that order rather than together.** Physical access exists at E2, translation at E4, real bus cycles at E5; the staging table at the foot of this sheet is the honest form of the list above, and reading it as a set available on day one is the one way to be disappointed by this block.
  NOTE: Reading *through the MMU* is the capability that arrives last and matters most: it alone shows what the kernel believes, not what the memory holds.
  NOTE: Nothing on that list needs a running CPU, which is what makes E2 possible.
- R.2 — **The RP2354B is not a bus master.** It sends commands; the debug agent performs the access. Three reasons, none of them stylistic. **Pins**: mastering directly needs ~24 address plus 8 data lines plus control, well beyond what the EC has left after its committed functions — and its budget already had to be rescued once (→ [D1.6](sec_ai_d1#d16)). **Reuse**: Helium already owns the SRAM controller, the SDRAM controller with refresh, the cache and the arbiter; a second path to memory would duplicate all of it and become a second source of truth about memory state. **Coherence**: an external master bypassing the cache reads stale data whenever a dirty sub-block is resident in SRAM.
  NOTE: The consequence is the whole design in one line — the debug agent is **a peer of the CPU port in Helium's arbiter**, not a special case bolted to the side of it.
  NOTE: **The cost of that decision is that the agent inherits Helium's health.** Every capability is reached through a block which is itself part of the machine under test, so a Helium that did not configure, or whose clock is wrong, takes the whole debug path down with it — `DBG_ID` reading `$0000` is not a link fault ([R.8](sec_ai_r#r8)) but the instrument gone. It is the deliberate price of refusing a second path to memory, and it is why Neon's service port ([R.4](sec_ai_r#r4)) counts for more than it first appears: two blocks that fail apart.
  NOTE: Being a peer also means competing for bandwidth like one: a march test running while the CPU runs slows both, which is honest behaviour rather than a surprise.
- R.3 — **Helium drives `BE`**, not an RP2354B GPIO. Taking the bus requires two things in a defined order: the CPU releases its drivers, then Helium begins driving. Across the SPI link that ordering is a race across a clock-domain crossing with millisecond latency; inside Helium it is a synchronous state transition. Schematic consequence: `BE` routes Helium → CPU socket, and Helium's CPU-side address and data pins must be **bidirectional**, which lands on the I/O bank plan (→ [Q27](sec_ai_q#q27)).
- R.4 — **The register file is SPI-only and is not in bank `$FF`.** The agent is unconditionally privileged — it writes `$FF`, bypasses permission checks and halts the CPU — so exposing it to software would make the entire protection model depend on kernel correctness. Keeping the control path physically separate means no software failure can reach it, and the console stays usable precisely when software has failed, which is when it is needed (→ [M.1](sec_ai_m#m1), [Q22](sec_ai_q#q22)).
  NOTE: **There is a second debug path on this board now, and the two are worth seeing as a pair.** Neon reuses its four configuration SPI pins as a **service port** once `CDONE` rises, reaching its register file, its text buffer and font in block RAM, and its SDRAM ([T1.46](sec_ai_t1#t146)). This agent gives the EC memory and bus visibility from inside *Helium*; the service port gives it a **screen** and Neon's state from inside *Neon*. They share no logic and no chip select, so a fault in one does not take the other — and between them a machine with a dead CPU still has a way to say what is wrong, with nothing attached to it.
- R.5 — Two orthogonal axes characterise every transaction: **which address space** and **how far the cycle reaches**. They compose freely, and the console shows both in the prompt because getting them wrong is the commonest source of confusing results.
  NOTE: Four combinations, and the one that surprises is **virtual + external cycle**: translation *and* a cycle other devices can see. It is the last to arrive, at E5, because it needs both halves — which is why the prompt shows the axes rather than assuming them.

## The two axes — address space and transaction scope, chosen independently.

| Axis | Mode | What it means | Available from |
|---|---|---|---|
| Address space | Physical | 27-bit raw address, straight to cache and memory controllers. What is needed while the MMU is itself under test | E2 |
| Address space | Virtual | 24-bit address + ASID, through translation and, on a miss, the walker. Shows what the kernel believes it is looking at | E4 |
| Scope | Internal | SRAM, SDRAM and Helium's own registers. Nothing appears on the CPU bus | E2 |
| Scope | External cycle | Everything the CPU can reach — the `$FE` VRAM aperture and the rest of `$FF` included. Indistinguishable, from outside, from a cycle issued by the 65816 | E5 |

- R.6 — Link: **SPI mode 0, RP2354B controller, Helium peripheral — and since REV C the agent is not a slave of its own but endpoint `0x02` of the one link** ([D3.9](sec_ai_d3#d39), [D3.12](sec_ai_d3#d312)). It shares `SCK`/`MOSI`/`MISO` with the configuration SPI as it always did, and now shares `LINK_CSN` too. **`DBG_CSN` is withdrawn** ([D80](sec_ai_q#d80)).
  NOTE: **The argument this item used to make for a dedicated select was wrong, and it is worth saying which part.** *Sharing data lines is acceptable, sharing the chip select is not, because the configuration path has to keep working when the agent is in an unknown state* — but the configuration path is disjoint in time from any runtime traffic, and the select the agent shares is the **runtime** one rather than `CFG_SS_A`, which is separately parked low ([D3.8](sec_ai_d3#d38)). **What the second select actually bought was addressing, and a header byte buys it more cheaply** ([D3.9a](sec_ai_d3#d39a)).
  NOTE: **The isolation the select was credited with survives it, because it never came from the select** ([R.26](sec_ai_r#r26)).
  NOTE: [[open]] **Two clock figures are now in the document and only one can be right.** This sheet has carried **16 MHz initially**, limited by the synchroniser depth on Helium's side rather than the wire; the transport note computes every frame and boot-load figure at **10 MHz** ([D3.12a](sec_ai_d3#d312a), [R.25](sec_ai_r#r25)). The router adds the header FSM and two CRC-8 generators to that path, so the old number cannot simply be assumed forward. **10 MHz is the conservative figure the budgets are written against until the ceiling is measured** (→ [Q153](sec_ai_q#q153)).
- R.7 — Frame: the agent's own frame is now the **payload of a link frame addressed to endpoint `0x02`**, and its shape is unchanged inside that — one header byte, bit 7 is `0` write / `1` read, bits 6:0 the register address, then data **least-significant byte first**. The link's `HCRC`, `FCRC` and acceptance rules sit around it ([D3.11b](sec_ai_d3#d311b), [D3.11c](sec_ai_d3#d311c)), and a frame commits on the rising edge of `LINK_CSN` as it used to on `DBG_CSN`.
  NOTE: **What did change is the length of a streaming read, and it is a real loss rather than a notational one.** `DBG_FIFO` and `TRC_FIFO` used to stream for as long as the select stayed low, so a kilobyte dump cost one frame. **`LEN` is one byte, so a frame now carries at most 251 payload bytes** and a kilobyte takes five of them — which is the price of the head-of-line bound that keeps a bulk dump from locking out HID for tens of milliseconds ([D3.12a](sec_ai_d3#d312a)). Four bytes of framing per frame is 1.6 % overhead, and the ring buffer read of [R.16](sec_ai_r#r16) is now a loop rather than a single transaction.
- R.8 — `DBG_ID` reads `$6516`, and the console reads it first: a correct value proves the SPI link, Helium's configuration and the clock all at once, before anything else is attempted. `$0000` or `$FFFF` means the bitstream did not load. A second read in the same frame returns the gateware build revision, which is bumped on every synthesis.
  NOTE: `$6516` is not arbitrary — it reads as the part number, which makes a wrong value obvious on a console with no other output yet.
- R.8a — **First contact, in the order the console performs it — each step discriminates a different failure.** **Endpoint `0x01` first, which is new at REV C**: magic, protocol version and gateware build ID from the router itself, answering even while every other endpoint is held in reset ([D3.12](sec_ai_d3#d312)) — so *the router is alive but the agent is not* stops looking like *nothing is alive*. Then `DBG_ID` ([R.8](sec_ai_r#r8)) — the agent, its configuration and its clock in one read. Then the build revision from the second read of the same frame, which says whether the part runs the bitstream just synthesised or a stale image from flash. Then `DBG_STATUS`, which answers even with `DEBUG_ENABLE` deasserted ([R.18](sec_ai_r#r18)), so "jumper off" and "agent broken" stop looking alike. Then clear `DBG_ERR`: [R.9](sec_ai_r#r9)'s latch may be set from a previous session, and every command after it refused. Only then an **internal** read of a known SRAM location, proving the arbiter path and the cache controller with no cycle on the CPU bus — and only after that anything virtual ([E4](sec_ai_p3#e4)) or external ([E5](sec_ai_p3#e5)).
  NOTE: `$0000` or `$FFFF` from `DBG_ID` means no bitstream; a correct ID with `DBG_STATUS` refusing is `DEBUG_ENABLE` off; a correct ID with the first internal read timing out is [R.17](sec_ai_r#r17)'s watchdog — the agent is alive, the memory path is not.
- R.9 — Two disciplines the console must observe. **Never assume a command completes inside the frame that issued it** — an SDRAM access with a page miss and an intervening refresh takes far longer than an SRAM hit, so poll `BUSY`. And **the agent latches the first error and refuses further commands until `DBG_ERR` is cleared**, which is what stops a scripted burst from quietly producing a page of garbage after its first failure.
  NOTE: Both disciplines are the console's: gateware cannot enforce either.
- R.10 — Access width, corrected against the memory the board actually has. The system SRAM is **1 MB ×8 with D0–D7 shared with the CPU nets** (→ [D15](sec_ai_q#d15)), so it has no upper/lower byte enables and a 16-bit access is simply two consecutive byte cycles. Byte granularity does bite on the SDRAM side, which is ×16 and masks with `DQM`. `DBG_WIDTH` therefore selects **8-bit low · 8-bit high · 16-bit**, and the E2 memory test must still exercise byte writes explicitly: a byte write that corrupts its neighbour is a very specific and very confusing failure, and it is cheaper to find it with `mt` than through a kernel bug.
  NOTE: This register was specified against an IS61WV102416 ×16 SRAM with `UB#`/`LB#`. That part predates [D15](sec_ai_q#d15) and is not on this board; the register keeps its encoding, its justification changes.
  NOTE: On the SRAM side an odd byte count is no special case — only a last access.
  NOTE: On an ×8 memory low-versus-high is an address, not a byte enable: `DBG_WIDTH` picks which of the two cycles happens, and the SRAM never learns which half it served.

## Register map — SPI address space, 7 bits, entirely separate from the `$FF` block of [sheet M](sec_ai_m).

| Addr | Name | Access | Width | Meaning |
|---|---|---|---|---|
| `0x00` | `DBG_ID` | RO | 16 | Magic `$6516`; second read returns the build revision |
| `0x01` | `DBG_CTRL` | RW | 8 | `ENABLE` · `VIRT` · `EXTCYC` · `AUTOINC` — advances `DBG_ADDR` by the access width after each access, and **not** after an error, so a failed burst leaves the address on the element that failed · `NOCACHE` · `STALL` — `0` steals cycles where it can, `1` stalls PHI2 for every access |
| `0x02` | `DBG_STATUS` | RO | 8 | `BUSY` · `DONE` · `ERROR` · `FIFO_EMPTY` · `FIFO_FULL` · `CPU_HALTED` · `TRC_TRIGD` · `DBG_READY` |
| `0x03` | `DBG_ERR` | RO/W1C | 8 | `TIMEOUT` · `UNMAPPED` · `PERM` · `ARB` · `CMD` · `STATE` · `FRAME` · `ALIGN` |
| `0x04` | `DBG_ADDR` | RW | 32 | 27-bit physical, or 24-bit virtual; unused high bits must be zero |
| `0x08` | `DBG_DATA` | RW | 16 | Data port for single accesses |
| `0x0A` | `DBG_WIDTH` | RW | 8 | `1` low byte · `2` high byte · `3` 16-bit (→ [R.10](sec_ai_r#r10)) |
| `0x0B` | `DBG_ASID` | RW | 16 | ASID for virtual accesses. Narrows when [Q24](sec_ai_q#q24) lands |
| `0x0C` | `DBG_CMD` | WO | 8 | Command trigger; rejected with `ERR_STATE` while `BUSY` |
| `0x0D` | `DBG_COUNT` | RW | 16 | Burst length in elements |
| `0x10` | `CPU_CTRL` | RW | 8 | `RESET` · `HALT` · `STEP` · `STEP_INSN` · `IRQ_MASK` · `NMI_MASK` |
| `0x11` | `CPU_STATUS` | RO | 8 | CPU state |
| `0x12` | `CPU_CYCLES` | RO | 32 | Free-running bus-cycle counter |
| `0x18` | `TRC_CTRL` | RW | 8 | `EN` · `ARM` · `ONESHOT` · `POS` · `HALT_ON_TRIG` · `FILTER_OPFETCH` |
| `0x19` | `TRC_STATUS` | RO | 8 | Trace state and fill level |
| `0x1A` | `TRC_TRIG_ADDR` | RW | 32 | Trigger address, with `RWB`/`VPA`/`VDA` qualifiers in the upper bits |
| `0x1E` | `TRC_TRIG_MASK` | RW | 32 | Trigger don't-care mask |
| `0x1F` | `TRC_FIFO` | RO | burst | Trace record readout |
| `0x20` | `DBG_FIFO` | RW | burst | 512-byte bulk data port, sized to stay ahead of the link across an SDRAM page miss. **The agent never stretches the SPI clock**, so the console is the side that honours `FIFO_FULL` on writes and `FIFO_EMPTY` on reads |
| `0x30` | `TLB_INDEX` | RW | 16 | TLB entry selector |
| `0x31` | `TLB_ENTRY` | RO | 64 | TLB entry readout |
| `0x38` | `MMU_MIRROR` | RO | 8 | Read-only view of `MMU_STATUS` (→ [sheet M](sec_ai_m)) |
| `0x40` | `EC_PWR_STATE` | RO | 8 | **Always accessible**, `DEBUG_ENABLE` notwithstanding: `SYS_REQ` · `REQ_REBOOT` · `IS_ACK` · `IS_NAK` · `CPU_ACK_SEEN` (→ [S.9](sec_ai_s#s9)) |
| `0x41` | `TELEM_CTRL` | WO | 8 | **Always accessible**: `TELEM_COMMIT` · `TELEM_EVENT_SET` |
| `0x42+` | `TELEM_STAGE` | WO | 16 B | **Always accessible**: the staging bank, written byte by byte in any order (→ [S.16](sec_ai_s#s16)) |

## Commands — written to `DBG_CMD`, one at a time.

| Code | Name | Action |
|---|---|---|
| `0x00` | `CMD_NOP` | No operation; clears `DONE` |
| `0x01` · `0x02` | `CMD_READ` · `CMD_WRITE` | One element through `DBG_DATA` |
| `0x03` · `0x04` | `CMD_READ_BURST` · `CMD_WRITE_BURST` | `DBG_COUNT` elements through the FIFO |
| `0x05` | `CMD_FILL` | Write `DBG_DATA` to `DBG_COUNT` consecutive elements |
| `0x10` · `0x11` | `CMD_CACHE_FLUSH` · `CMD_CACHE_INVAL` | Flush the whole cache to SDRAM · invalidate it without writeback. **`INVAL` discards dirty data** and exists only to recover a wedged cache during gateware bring-up |
| `0x12` | `CMD_CACHE_FLUSH_LINE` | Flush the line holding `DBG_ADDR` — the same operation the kernel needs before paging a frame out (→ [F.7](sec_ai_f#f7)) |
| `0x20` · `0x21` | `CMD_TLB_PROBE` · `CMD_TLB_FLUSH` | Translate `DBG_ADDR` into `TLB_ENTRY` · invalidate the whole TLB |
| `0x22` | `CMD_PTWALK` | Full page-table walk, bypassing the TLB |
| `0x30` | `CMD_ABORT` | Cancel the in-flight command |

  NOTE: **`CMD_READ_BURST` and `CMD_WRITE_BURST` are not [R.25](sec_ai_r#r25)'s `READ_BURST` and `WRITE_BURST`, and the two must not be conflated.** These are register-model commands: `DBG_ADDR` and `DBG_COUNT` are loaded first and the data streams through `DBG_FIFO`, so **the address lives in a register across frames** — which is precisely the cross-frame state that forbids a streaming commit. [R.25](sec_ai_r#r25)'s form carries its own absolute address in every frame and is the only one the boot load uses. The register form stays for interactive work, where a console already holds the address.
  NOTE: [[open]] **Two opcode spaces both use `0x10` and `0x11` and they are unrelated.** In `DBG_CMD` those are the cache flush and invalidate above; in the endpoint `0x02` payload they are `WRITE_BURST` and `READ_BURST`. **Nothing decodes them together and nothing breaks** — but a reader, a firmware author or a testbench will conflate them at least once, and renumbering one space before either is implemented is nearly free (→ [Q157](sec_ai_q#q157)).

- R.11 — `CMD_PTWALK` earns its place by differing from `CMD_TLB_PROBE` in exactly one way: it always reads the table from memory. **Comparing the two is the direct test for a stale TLB entry** — which is the precise failure the `CTX_SET_PTBASE` before `CTX_SET_ASID` ordering invariant exists to prevent, and which otherwise has no symptom until something is corrupted (→ [M.8](sec_ai_m#m8)).
  NOTE: The comparison runs the other way too, and that is its use at E4. With no kernel in existence the console writes a page table by hand, walks it with `CMD_PTWALK` and probes it with `CMD_TLB_PROBE`: agreement validates the walker against a table the engineer wrote, disagreement localises the fault to one of the two. A walker is otherwise hard to test before anything exists that can fault (→ [M.2](sec_ai_m#m2)).
  NOTE: The comparison only means anything with the same ASID loaded for both.
- R.12 — The access path: `IDLE` → decode → translate if `VIRT` → arbitrate → then either an internal access through the cache, or `BUS_TAKE` · `BUS_CYCLE` · `BUS_RELEASE` for an external one → complete. Only the external branch touches the CPU, and its sequence is fixed: request the bus, stall PHI2 at a clean cycle boundary, assert `BE` low, wait the CPU's tristate turnaround, drive the cycle, release the drivers, wait turnaround, deassert `BE`, release PHI2 and the arbiter.
  NOTE: The restart must meet the minimum PHI2 pulse width. The existing glitch-free gating logic is reused unchanged — the agent is one more client of it, not a second implementation (→ [D16](sec_ai_q#d16)).
- R.13 — Coherence, four rules. **One: the agent goes through the cache controller**, exactly as the CPU port does, so a physical read of an SDRAM address whose sub-block is dirty in SRAM returns the cached value. This is not negotiable — a debug tool that reports memory contents differing from what the CPU sees is worse than no tool at all, because it produces confident wrong answers during exactly the sessions where the engineer can least detect them. **Two: `NOCACHE` is for gateware bring-up only** — its one legitimate use is validating the cache itself (write through the cache, flush, read with `NOCACHE`, compare), and the console prints a warning banner whenever it is set. **Three: external cycles are coherent by construction**, being decoded by the same logic as a CPU cycle. **Four: writing a PTE does not invalidate the TLB** — the console's `pt write` issues `CMD_TLB_FLUSH` afterwards; anyone driving the registers directly must do the same (→ [M.7](sec_ai_m#m7)).
- R.14 — CPU control is an **indefinite PHI2 stall**, legal because the core is fully static (→ [E.4](sec_ai_e#e4), [D16](sec_ai_q#d16)). `STEP` advances one bus cycle, `STEP_INSN` runs to the next opcode fetch — which `VPA & VDA` identifies, the same pins the MMU already needs for the `X` permission (→ [E.3](sec_ai_e#e3)). `IRQ_MASK` and `NMI_MASK` matter more than they look: a 100 Hz timer that keeps running while the CPU is stopped presents a backlog of pending interrupts on resume, which looks exactly like a kernel bug and is not.
  NOTE: `STEP_INSN` finds the next opcode fetch, and with interrupts unmasked that fetch may be the handler's first: stepping *over* an instruction and *into* an interrupt look identical from outside. That is what the masks are for.
- R.15 — **The agent cannot read the CPU's registers.** The W65C816S has no scan chain and no debug port; A, X, Y, S, DP, DBR, PBR and P are not observable from outside, and no amount of gateware changes that. Two workarounds, in order of preference: **inferred from trace** — a halt at an instruction boundary plus the preceding cycles lets the console reconstruct PC and much of the state, passively and always; and a **debug stub** in bank `$00` that pushes every register to a known location, entered either by forcing an instruction onto the data bus during a fetch or from a `BRK` breakpoint trap (→ [J.3](sec_ai_j#j3)). The console exposes the first as `reg` and the second as `reg -f`, and **the distinction stays visible to the user**: silently perturbing state during inspection is unacceptable in a debugger.

- R.16 — Trace: a ring buffer in EBR capturing, per bus cycle, address (24), data (8), `RWB`, `VPA`, `VDA`, `VPB`, `MLB`, `E` and a cycle-counter delta — about 48 bits per record. The trigger compares `(address & ~TRC_TRIG_MASK)` against `TRC_TRIG_ADDR`, optionally qualified by `RWB` and `VPA`/`VDA`, and can position the capture at the start, centre or end of the window, halt the CPU when it fires, or filter down to opcode fetches only. **This is a logic analyser for one EBR block and a comparator, and it must be built with the CPU stage rather than retrofitted after the first hard kernel bug.** The mask is a don't-care mask rather than a match mask — `TRC_TRIG_MASK` bits set are the bits ignored — so an exact address is mask zero and a 2 KB page is a mask of eleven ones, which is what makes "trigger anywhere in this page" a single comparator rather than a range check. The buffer is read back through `TRC_FIFO`, which streams for the length of a frame's payload ([R.7](sec_ai_r#r7)), so dumping the ring costs a frame per 251 bytes rather than one per record — and no longer one frame for the whole ring, which is what the head-of-line bound of [D3.12a](sec_ai_d3#d312a) costs here. [[open]]
  NOTE: 1024 records is the starting proposal, but the depth is a synthesis parameter against an EBR budget that the TLB and the cache tags are already spending (→ [Q30](sec_ai_q#q30)). That figure was costed on an HX4K; Helium is an **HX8K** (→ [B.2](sec_ai_b#b2)).
  NOTE: The depth is not free and the arithmetic is the reason it is a parameter: 48 bits is six bytes, so 1,024 records are 6 KB of a device that has 16 KB of EBR in total — and the TLB and the cache tags are spending it first ([B.2](sec_ai_b#b2)).
  NOTE: The cycle-counter delta is counted in Helium's core clock, not in PHI2 edges, which is the only reason it survives [L.15](sec_ai_l#l15): a stalled cycle appears as a long delta rather than as a gap the trace cannot account for.
  NOTE: Filtering to opcode fetches turns the same buffer into an instruction trace.
- R.17 — Every transaction is covered by a watchdog — 100 µs at the Helium core clock as a starting value, generous enough for a worst-case SDRAM access with an intervening refresh and short enough that a human reads it as a delay. On expiry the agent abandons the transaction, releases the bus and PHI2, sets `ERR_TIMEOUT` and returns to idle. **The agent must never be able to hang the console**, and that constraint outranks completing any transaction: if it hangs, the engineer loses the only view into a board that is, by hypothesis, already misbehaving. Abandoning is not simply stopping: the external branch of [R.12](sec_ai_r#r12) is unwound in reverse — drivers released, turnaround waited, `BE` deasserted, PHI2 restarted at a legal pulse width — since a timeout that left the CPU tristated or its clock stopped would turn a slow transaction into a dead machine. `ERR_TIMEOUT` then latches like any other error and blocks further commands until it is cleared ([R.9](sec_ai_r#r9)), so a script cannot walk past the first timeout and report a page of zeros.
  NOTE: The reverse interaction has to be handled too — the system watchdog that turns a hung fill into NMI or ABORT must be **suppressed while the CPU is halted by the agent**, or every debug session ends in a spurious abort.
  NOTE: 100 µs sits between two bounds: longer than the slowest legal transaction — an SDRAM access whose row is closed and whose refresh lands mid-way — and short enough to read as a delay rather than a hang.
  NOTE: **This board now has three watchdogs and they do not overlap.** [F.11](sec_ai_f#f11)'s bounds a cache fill in microseconds, this one a debug transaction on the SPI side, and [S.7](sec_ai_s#s7)'s a kernel's shutdown acknowledgement in seconds. Each covers a case the others cannot see, so none can be dropped for another.
  NOTE: [[!blocking]] **100 µs was chosen when nothing depended on the agent, and something does now.** The boot load runs through this watchdog on every power-up ([R.25](sec_ai_r#r25)), so a timeout that was a diagnostic has become **a failed boot**. The value must be re-derived against worst-case SDRAM latency — a row activation coinciding with a refresh cycle, under whatever the boot load's own access pattern turns out to be — or the machine will fail to boot intermittently under exactly the conditions that are hardest to reproduce (→ [Q155](sec_ai_q#q155)).
  NOTE: A watchdog that fires is itself data — it says where answering stopped.
- R.18 — `DEBUG_ENABLE`, a Helium input on a jumper, gates the whole thing: deasserted, it forces `DBG_CTRL.ENABLE` to zero, ignores writes to it, and rejects every command with `ERR_STATE` — while still answering `DBG_ID` and `DBG_STATUS`, so the console can report *why* it is refusing rather than appearing broken. The point is not security against physical access, which is unachievable and not a goal, but making the privileged path an **explicit, visible, deliberate state of the board**.
  NOTE: The gate now has a **documented hole, and it has to be one**: `EC_PWR_STATE` and the telemetry staging registers sit outside it. Power management is a production function, not a debug function, and putting it behind the strap would break shutdown and battery reporting on every board built with debug disabled. Neither register can initiate a bus cycle or reach memory, so the region grants nothing the strap exists to withhold — but it must be carved out of the map deliberately, and confirming it can be without disturbing what is already there is [Q38](sec_ai_q#q38).
  NOTE: [[open]] **The gate now has a second hole and it is larger than the first.** `bios.bin` reaches SRAM through this block ([R.25](sec_ai_r#r25)), so **a strap that rejected every command would stop the machine booting** — and `WRITE_BURST` has to be permitted with `DEBUG_ENABLE` deasserted while halt, step, trace and register access are refused. That is a selective decode inside one endpoint rather than a gate in front of it, which is the reverse of what [D3.2](sec_ai_d3#d32) was written to claim. **If the strap survives, this is the form it takes; the decision is [Q125](sec_ai_q#q125).**
  NOTE: The jumper is a production decision as much as a security one. [R.4](sec_ai_r#r4)'s argument — the agent bypasses every permission check and halts the CPU — applies to a stranger with four wires as much as to a kernel bug: a shipped board with the agent enabled hands over the whole address space.
- R.19 — The console is a **physical UART**, 115200 8N1, on the `J-DBG` header — and it is the only transport, because the EC's USB is committed to host mode and there is no device port to put a CDC console on ([D1.9](sec_ai_d1#d19)). The mirrored USB-CDC of an earlier arrangement is gone with it; nothing above this line depended on having two.
  NOTE: **What the loss costs is a diagnostic, and it is worth naming rather than glossing.** Two transports used to let you tell a firmware fault from a USB stack fault at the first stage, by seeing which one still answered. With one transport that discrimination is gone — and it is largely paid back by there no longer being a USB stack under the console to be at fault, and by the rescue debug port of [D1.13](sec_ai_d1#d113), which reaches a chip whose firmware has stopped answering anything.
  NOTE: **The header that carries it is the same one that carries SWD**, which closes the case this NOTE used to make for putting two headers beside each other: `J-DBG` is five pins — `SWCLK`, `SWDIO`, `GND`, `TX`, `RX` — and one probe services both over one cable ([D1.12](sec_ai_d1#d112)). They survive onto the target board for [E1.4](sec_ai_p3#e14)'s reason: a header cannot be added to a board already spun.

## Console grammar — hexadecimal by default, `#` prefixes decimal, `p:` and `v:` qualify an address.

| Group | Commands | Notes |
|---|---|---|
| Memory | `md` · `mw` · `mf` · `mc` · `ms` · `mt` | dump · write · fill · compare · search · test (march-c, addr-in-addr, walking-1) |
| Mode | `mode phys / virt` · `int / ext` · `asid <n>` · `width 8 / 16` · `nocache on / off` | bare `mode` prints the current flags; `nocache` prints a warning |
| CPU | `halt` · `run` · `step [n]` · `stepi [n]` · `reset [hold]` · `reg` · `reg -f` · `dis` | `reg` infers from trace, `reg -f` forces the stub and perturbs state (→ [R.15](sec_ai_r#r15)) |
| Trace | `trace arm [addr] [mask]` · `on / off` · `pos` · `dump [n]` · `filter opfetch` | `dump` disassembles the records |
| MMU | `tlb dump / probe / flush` · `pt walk / dump / write` · `cache flush / inval / stats` | `pt walk` shows each level; `pt write` flushes the TLB after it |
| Storage | `ld <file> <addr>` · `sv <addr> <len> <file>` · `boot <file>` | straight from the microSD the EC already owns (→ [G.2](sec_ai_g#g2)) |
| System | `id` · `status` · `err` · `help [cmd]` | `status` decodes every status bit; `err` decodes and clears |

- R.20 — Five behavioural requirements, each of them a lesson rather than a preference. **Every error is reported with its decoded cause** — never a bare failure. **Long operations show progress**: a march test over 64 MB of SDRAM takes minutes, and a silent console for that long is indistinguishable from a hang. **Ctrl-C aborts** through `CMD_ABORT`. **`md` output is annotated** with the region it fell in — cached SRAM, pinned SRAM, SDRAM, VRAM aperture, `$FF` — derived from the physical map of [L.6](sec_ai_l#l6). **The prompt carries the mode**: `p16>` for physical 16-bit, `v8:0042>` for virtual 8-bit under ASID `$42`.
  NOTE: **The console is the reference implementation of [R.9](sec_ai_r#r9), not a convenience laid over it.** Each of the five is a discipline that any other driver of these registers — a script, a GDB stub, a test harness — has to reproduce for itself, because the agent enforces none of them: it latches an error and refuses, and turning that into a legible failure is entirely the business of whatever holds the SPI.
- R.21 — What the agent settles that was open before it: **[Q25](sec_ai_q#q25) — how the RP2354B reaches Helium's control registers with the CPU held in reset.** It does not master the bus; it issues an internal access, and an internal write to a `$FF:00xx` address meets the same address comparator a CPU store would. So the whole "address as opcode" command model of [sheet M](sec_ai_m) — TLB flushes, context loads, cache flushes and their `BUSY` discipline — becomes testable at E4 with no CPU, no BIOS and no kernel in the picture (→ [M.2](sec_ai_m#m2), [D18](sec_ai_q#d18)).
  NOTE: What it does not settle is worth listing beside it: it cannot show the CPU's registers ([R.15](sec_ai_r#r15)); it inherits Helium's health, so a Helium that did not configure takes the whole path with it; and it says nothing before that configuration, which is the half Neon's service port covers ([R.4](sec_ai_r#r4)).

## Staging — the agent's capability mapped onto this document's stages ([sheet P2](sec_ai_p2), [sheet P3](sec_ai_p3)).

| Stage | Debug agent capability | What it validates |
|---|---|---|
| E1.6 · RP2354B alone | Console up on the debug-port UART; **bitstream and `bios.bin` read out of EC flash** | EC firmware, the flash layout of [D1.21](sec_ai_d1#d121), the console transport. **No SD stack — there is none in EC firmware** ([D60](sec_ai_q#d60)) |
| E1 · the link alone | **Endpoint `0x01` answers** — magic, protocol version, build ID; a corrupted `HCRC` returns `NACK_HCRC`; `EP = 0x00`, `0xFF` and an unassigned value each return their own code | The SPI front end, the router, the header FSM and both CRCs — **before any endpoint exists to blame** ([E1.7](sec_ai_p3#e17)) |
| E1.7 · the three FPGAs | `DBG_ID` reads `$6516`; and on Neon's side, **a correct text screen plus glyphs written over the service port** — Neon stage N0 ([T1.64](sec_ai_t1#t164)) | SPI link, Helium clock, bitstream actually loaded — and, on Neon, the PLL, the timing generator, block-RAM initialisation, the panel and the FPC |
| E2 · SRAM + monitor | Physical peek/poke; `mt` march test; byte-write check | SRAM controller, shared-net timing, `md`/`mw` end to end |
| E3 · SDRAM | Physical SDRAM access; `CMD_CACHE_FLUSH`/`INVAL`; `cache stats` | SDRAM controller, refresh under load, cache coherence |
| E4 · MMU + cache + protection | Halt · step · trace; virtual mode; `TLB_PROBE` vs `PTWALK`; internal writes to `$FF` | PHI2 gating, `BE` handoff, arbiter, walker, ASID, [sheet M](sec_ai_m)'s command model |
| E5 · video + audio | External cycles into the `$FE` aperture, **reads included** — with `BE` low there is no PHI2 to stall, so the agent simply waits for `NEON_BUS_BSY` to clear before sampling D0–D7 ([T1.18](sec_ai_t1#t118)) | Inter-FPGA bus visibility, the VRAM window, Neon's decode — and framebuffer dumps, which is how blitter output gets compared byte-for-byte against a software reference with no kernel in existence |

- R.22 — **E2 is the stage that pays for the whole design.** Being able to march-test SRAM before any CPU exists converts the hardest class of bring-up bug — intermittent memory faults surfacing as random software misbehaviour — into a direct, reproducible measurement, and it does so at the exact moment the board is least able to explain itself. The alternative is not a slower measurement but a circular one: without the agent, the first read of that SRAM comes from a CPU fetching its own instructions out of it, so the instrument and the subject are the same part — and a memory fault presents as a processor that misbehaves.
  NOTE: The free-run stage before it ([E1.8](sec_ai_p3#e18)) gains too, if the trace buffer is ready: a captured NOP run reads PHI2, reset and the address bus with no analyser.
  NOTE: It is also what makes the sheet worth its pins: everything after E2 extends an existing path, so translation, bus cycles and trace cost gateware, not board.
  NOTE: The economics are worth stating once. A marginal SRAM fault found at E2 costs a march test and a reflow; the same fault at E6 costs days of suspecting the kernel, the toolchain and the cache in turn, since each is a better-known suspect than the memory. The stage does not make the bug rarer, it makes it cheap to name.
- R.23 — Honest cost, **one pin cheaper at REV C than it was written**. In pins: `DEBUG_ENABLE`, `BE` from Helium, optionally `DBG_IRQN` — which asserts on a trace trigger or a CPU halt, and buys only the difference between an interrupt and a poll — the 3-pin UART header, and bidirectional CPU-side pins on Helium. That lands on a budget which **does not close as written** — [Q8](sec_ai_q#q8) already had the free 17 pins failing to cover SPI-SD, the console UART and this port. Two of those are not chargeable to the agent, and the accounting should say so: `BE` is driven by Helium for cache fills whether or not a debug port exists ([F.4](sec_ai_f#f4)), and the UART header hangs off the RP2354B, not Helium. The agent's own marginal cost **was** `DBG_CSN`, `DEBUG_ENABLE` and an optional `DBG_IRQN`; with the agent moved onto the shared link it is **`DEBUG_ENABLE` and an optional `DBG_IRQN` — one pin, or two with the interrupt** ([D80](sec_ai_q#d80)). [[!blocking]]
  NOTE: In gateware the open items are the SPI-to-core clock-domain crossing (→ [Q28](sec_ai_q#q28)), the `BE` turnaround count at 3.3 V (→ [Q27](sec_ai_q#q27)), where the agent sits in the arbiter's priority order (→ [Q29](sec_ai_q#q29)), and the trace depth against remaining EBR (→ [Q30](sec_ai_q#q30)).
  NOTE: **`DBG_CSN` was the item this NOTE used to say could not be shared, and it has been.** The order of relief is now `DBG_IRQN` first, since polling costs only latency; then the pending bitmap of [D3.11a](sec_ai_d3#d311a) makes even that mostly redundant; then nothing — `DEBUG_ENABLE` cannot be shared, because a gate software can reach is not a gate ([R.18](sec_ai_r#r18)).
  NOTE: Nor are these pins allocated alone: [S.3](sec_ai_s#s3) assigns `EC_PWR_REQ` and `SYS_PWR_REQ` alongside them, so port and handshake close or fail as one item (→ [Q27](sec_ai_q#q27)).
- R.24 — Deferred, not ruled out: **breakpoint comparators** — address match forcing a halt, a natural extension of the trace trigger, held back to keep the CPU stage small · **watchpoints on data value** as well as address · and a **GDB remote serial protocol stub** on the RP2354B, so a host debugger drives the agent directly. The last is attractive and cheap to get wrong early; it is worth doing only once the command set above has stopped moving. The costs are known even if the dates are not: a comparator is a register pair compared against the address the trace already carries, watchpoints add the data byte to that compare, and the stub is firmware. None of the three needs a board change, which is what makes deferring them safe rather than merely convenient. [[open]]
  NOTE: The order is not arbitrary. Comparators and watchpoints are gateware, competing for the EBR [Q30](sec_ai_q#q30) is already short of; the GDB stub is firmware and costs no silicon at all, which makes it the tempting one to begin with and the wrong one — a remote protocol frozen against a command set still moving becomes a second thing to keep in step, and the audit it then needs is the one this sheet has so far been able to avoid.
  NOTE: The stub carries a dependency the other two do not. A host debugger asks for registers first, and [R.15](sec_ai_r#r15) says the part cannot give them — so a GDB stub is only as good as the inference from trace, or it drags in the intrusive stub and perturbs the state it was asked to report. That decision belongs with the stub, not after it.

## The boot load and the invariant — what REV C moved into this block.

- R.25 — **Boot memory loading and debug memory writes are the same operation, and REV C stops expressing them as two.** Both are a requester in Helium's arbiter writing physical memory through the cache controller; REV B had them as the mailbox's `MEM_WRITE` command class and this sheet's register path, which is one mechanism described twice. **The `MEM_WRITE` class is withdrawn and `bios.bin` is loaded through endpoint `0x02`** ([D3.2](sec_ai_d3#d32), [D82](sec_ai_q#d82)).
  NOTE: **The register-at-a-time model of `DBG_ADDR` · `DBG_DATA` · `DBG_WIDTH` · `DBG_CMD` is unusable for tens of kilobytes, so a bulk form is added.** `WRITE_BURST` is opcode `0x10`, then a **24-bit absolute address, big-endian**, then up to **251 data bytes** — the payload of one link frame. `READ_BURST` is `0x11` and symmetric: opcode, address and a length byte out, data back in the `MISO` payload. The register map is otherwise unchanged.

```
payload  0        1..3               4 … LEN-1
         OPCODE   ADDR[23:16..7:0]   data bytes
```

  NOTE: **The address is absolute in every frame and no address state persists between them.** Auto-increment operates inside a frame only. **This is what makes the streaming commit of [D3.11c](sec_ai_d3#d311c) sound**: a frame the link rejects on `FCRC` is retransmitted verbatim and rewrites the same bytes to the same addresses, so there is no pointer to desynchronise and no recovery procedure to write. The rule exists to buy that property, not to simplify the opcode.
  NOTE: **Boot time is not a constraint on this at any plausible image size.** At 10 MHz with 251-byte data frames the link carries about **1.23 MB/s**, so a 64 KB `bios.bin` lands in roughly 53 ms and 256 KB in roughly 213 ms — against a whole-boot budget already in the low hundreds of milliseconds ([D1.22](sec_ai_d1#d122)). The image size itself is still unmeasured (→ [Q127](sec_ai_q#q127)).
  NOTE: **What the consolidation buys, beyond one fewer requester in the arbiter.** **Every boot exercises the debug write path**, so it cannot rot unnoticed between debug sessions. **A failed load produces an error code the EC reports on the console** rather than a silent bad boot. And the two mechanisms can no longer disagree about what a write to physical memory means.
  NOTE: [[!blocking]] **What it costs is that the boot path now depends on this state machine**, which was instrumentation and is now boot-critical — the watchdog of [R.17](sec_ai_r#r17) fires during boot, and [R.18](sec_ai_r#r18)'s strap can no longer gate the block wholesale. **The abandonment condition is written down rather than left to improvisation**: if the agent proves too heavy or too unstable to be boot-critical by [E1.7](sec_ai_p3#e17), the load falls back to a dedicated write-only sink endpoint at `0x05` using this payload format unchanged. The transport is unaffected and costs one small gateware block and one row of [D3.12](sec_ai_d3#d312)'s table (→ [Q154](sec_ai_q#q154)).
  NOTE: **The cache controller's state during the boot load is undefined and has to be settled before the first `WRITE_BURST` is written.** Bypass, write through, or allocate — the CPU is in reset so coherence is trivial, which is exactly why it will be decided by whatever the gateware happens to do unless it is decided on purpose (→ [Q156](sec_ai_q#q156)).
- R.26 — **INV-1 — the agent's request port has exactly one source, and that is the whole of its isolation.** Endpoint `0x02` of the router drives it; **no CPU-writable register and no path reachable from the 65816 address space may.** [R.4](sec_ai_r#r4) argued this property from the register file being SPI-only, and REV B additionally credited it to `DBG_CSN` — **wrongly, and the correction matters more than the pin.** It is a *connectivity* property, not a *decode* property: it holds or fails on what can reach the port, and the number of chip selects in front of it is irrelevant either way. **It is to be verified structurally rather than by reading the decode logic** ([D3.2](sec_ai_d3#d32)).
  NOTE: **Two of this sheet's open gateware items are closed by the transport rather than answered on their own.** `DBG_CSN` allocation disappears with the pin ([R.23](sec_ai_r#r23)), and **the SPI-to-core clock-domain crossing is now specified once, in the router, instead of twice in two front ends** — one asynchronous FIFO per endpoint with Gray-coded pointers ([D3.12b](sec_ai_d3#d312b), [Q28](sec_ai_q#q28)).
  NOTE: **The reset domain is the third thing this sheet gains and did not ask for.** The router sits above every endpoint, so **a debug command that resets Helium's system side no longer destroys the transport carrying it** — the router survives and answers `NACK_EP_RESET` on the agent's behalf ([D3.12c](sec_ai_d3#d312c)). Under REV B a reset command and a hung link were the same observation.
