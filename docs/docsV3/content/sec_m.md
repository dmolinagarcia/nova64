# Kernel–hardware interface
> Helium's control registers · command model · invariants

Helium owns three pieces of state ordinary memory accesses cannot reach: the TLB, the active context, and the write-back cache. This sheet is the interface the kernel drives them through — and it sits **strictly below the syscall layer**.

- M.1 — Three layers, kept deliberately apart: the **syscall ABI** (`COP`, visible to processes) · the **kernel's MMU and cache logic** (C and assembly in bank `$01`, kernel only) · **hardware control** (stores to bank `$FF`, this sheet, kernel only).
  NOTE: "Flush the TLB" and "flush a frame" must never become system calls: any process could then flush in a loop and degrade the whole machine — a trivial denial of service. They are steps *inside* `munmap`, inside the context switch, inside the page evictor. The command encodings therefore live in a numbering space entirely independent of the syscall numbers, and the two must never be aligned.
- M.2 — **Address as opcode.** Each command has its own address; the value written is the command's *argument*, not a command code — `sta f:$FF0010` with an ASID in A flushes that ASID's TLB entries. Against the alternative of one command register plus a separate argument register, this removes the value decoder inside Helium (leaving the address comparator that already exists), removes the argument register, reduces every command to a single bus cycle, and kills a whole bug class: there is no intermediate "argument written, command not yet triggered" state for an interrupt to split.
- M.3 — Why memory-mapped and not `WDM`. An earlier proposal captured `WDM` (`$42`, reserved by WDC, executed as a two-byte two-cycle no-op) and had Helium decode its signature byte. Rejected on four counts: memory mapping **widens a comparator that already exists** for the fault registers, where a WDM snooper needs a new state machine tracking VPA/VDA to tell an opcode fetch from an operand; it **inherits the protection keystone** free, since `$FF` is already unmappable to user space, where WDM would need its own privilege gate; it is **testable before a kernel exists**, with the RP2040 driving the bus in E1–E3; and it **keeps Argon honest** — a softcore need only implement the documented instruction set, not replicate a private decode table.
  NOTE: `WDM` stays a reserved no-op and Argon must implement it as one, decoding nothing. The single use it seemed to serve uniquely — a breakpoint insertable into user code, which cannot touch `$FF` — is already covered by `BRK` and its own vector.
- M.4 — The block lives at `$FF:0000–$FF:00FF`. All registers are 16 bits and are accessed with `M=0`; byte-granular access to one is undefined in this revision. Addresses not listed decode as no-ops on write and `$00` on read.
  NOTE: **Helium now claims a second block in bank `$FF`**: the power and battery registers of [sheet S](sec_s), which are byte-wide, are read a byte at a time by design, and use a value-decoded command register rather than address-as-opcode. They are deliberately kept behind their own 256-byte wall and out of this map — the power path must not depend on the cache, the arbiter or SDRAM, and mixing it into the MMU block would invite exactly that coupling. Its base address is still unassigned (→ [Q40](sec_q#q40)).
  NOTE: **And bank `$FF` now has a tenant that is not Helium at all.** Neon's register file sits at `$FF:8000`–`$FF:80FF`, physically on the other side of the shared bus, because `$FF` is the one bank a user process can never map and Neon's command processor is far too powerful to be reachable from one ([D36](sec_q#d36)). Two consequences for this sheet. **Helium's decode gains a hole**: at or above `$FF:8000` it must not answer, and on a read it must release D0–D7 and let Neon drive them — the same turnaround an `$FE` access already performs. And **"addresses not listed decode as no-ops on write and `$00` on read" stops being true of the whole bank** — it holds within Helium's half, `$FF:0000`–`$FF:7FFF`, and the upper half is Neon's to define (→ [T.21](sec_t#t21), [Q22](sec_q#q22)).
- M.5 — Two completion classes, split by whether the command touches SDRAM. **Synchronous** — every TLB and context operation finishes within the bus cycle of the write (a flush is clearing validity bits in EBR, a context update is a register load), so there is nothing to poll and the effect is visible to the very next cycle. **Asynchronous** — the cache flushes, which may run for microseconds.
- M.6 — Asynchronous commands **must not be implemented by stalling PHI2**, even though a bounded hardware operation nominally qualifies (→ [D16](sec_q#d16)). Holding PHI2 low blocks interrupt service, which would inject microseconds of scheduler jitter on every page eviction. The kernel polls `BUSY` instead — the page evictor is already slow kernel code and the spin costs nothing there.
  NOTE: **One case does stall PHI2, and it is worth saying why it does not contradict this.** A CPU read of Neon's `$FE` aperture holds the clock until `NEON_BUS_BSY` clears ([T.18](sec_t#t18)). The difference is the size and the shape of the cost: a cache flush runs for microseconds *on every page eviction*, in the middle of ordinary kernel work, where the jitter is unavoidable and repeated; a VRAM read costs a few hundred nanoseconds on an explicitly diagnostic path, and the alternative is not a `BUSY` poll but no read path at all. The rule this sheet states still holds — **do not stall PHI2 for something the kernel could poll instead** — and the one exception exists because there is nothing to poll (→ [D37](sec_q#d37)).
  NOTE: Gateware rules: `BUSY` must read 1 on the *first* read after the triggering write, never lag — a kernel sampling a stale 0 would proceed against a half-flushed frame. A write to an async register while `BUSY` is set is ignored: it neither queues nor aborts. Ordinary CPU traffic keeps being served throughout, slowed but never stalled, and the timer and interrupts keep running.
  NOTE: **Nothing covers a flush that never finishes, and it is the one gap this model leaves open.** [F.11](sec_f#f11)'s watchdog resumes PHI2 and raises NMI or ABORT when a fill overruns — but an asynchronous flush deliberately does not stall PHI2, so there is no clock to resume and that watchdog never fires. A hung SDRAM controller therefore strands the kernel in the `BUSY` spin loop above with nothing stopped, nothing raised and no diagnostic. What is wanted is a counter in Helium bounding how long a flush may run, escalating to NMI or `ABORTB` with its own `FAULT_CAUSE` code (→ [Q74](sec_q#q74)).
- M.7 — Ordering comes free. The W65C816S has **no prefetch queue and no store buffer**: every bus cycle is architectural and appears in program order, so a store to a command register takes effect strictly after everything before it and strictly before everything after. **No memory barrier is required, and none is provided.** A PTE written to SRAM before a `TLB_INVAL_PAGE` is guaranteed visible to the walker at the moment of invalidation.
- M.8 — Two invariants the kernel must uphold, both of which fail silently. **Write `CTX_SET_PTBASE` before `CTX_SET_ASID`**: an interrupt taken between them then still sees the old ASID, whose TLB entries remain consistent with the old table. Reversed, the new ASID is live while the walker still reads the old table — filling the TLB with wrong entries tagged as correct. **Flush an ASID before recycling it**: skip that and the previous process's translations leak into a fresh address space, a total protection failure with no symptom until something is corrupted.
- M.9 — One requirement on the gateware, not an optimisation: **the pinned region must be non-cacheable or write-through**. Page tables live there and the walker reads SRAM directly, so if CPU writes to table memory went through the write-back cache the walker could read a stale PTE. The `NC` flag exists in the PTE format for exactly this (→ [F.5](sec_f#f5)).
- M.10 — This block has a **second, deliberately asymmetric user**. The debug agent's internal accesses land on the same `$FF:00xx` address comparator a CPU store does, so every command below can be issued — and its `BUSY` discipline observed — with the 65816 held in reset and no kernel in existence; that is what makes the model testable rather than merely specified. The traffic is one-way: the agent's own register file is SPI-only and **is not mapped here**, because the block that can bypass the protection model must not be reachable through it (→ [sheet R](sec_r), [R.4](sec_r#r4)).
- M.11 — **Reaching this block costs more than it looks, and the cheap form is a convention rather than an optimisation.** Absolute long addressing — `sta f:$FF0010` — is 4 bytes and 5 cycles, and the `f:` prefix is not decoration: without it ca65 narrows the access to 16-bit absolute and the store lands in whatever bank `DBR` happens to hold. Any routine issuing two or more commands should set `DBR` to `$FF` on entry instead and use 16-bit absolute — `sta $0016` then `sta $0014` for a context switch — at 3 bytes and 4 cycles each.
  NOTE: This is one of the few places the fixed-`DBR` small-data model ([O.3](sec_o#o3)) is deliberately repointed, and it is confined to leaf assembly routines that push `DBR` on entry and restore it before returning. The MMU layer repoints it; nothing above the MMU layer does.

## Register map — base block `$FF:0000`. Helium owns `$FF:0000`–`$FF:7FFF`; the upper half is Neon's ([T.21](sec_t#t21)).

| Address | Name | Access | Meaning |
|---|---|---|---|
| `$FF:0000` | FAULT_ADDR_L | read | Faulting virtual address, bits [15:0] |
| `$FF:0002` | FAULT_ADDR_H | read | Bits [23:16] in the low byte; upper byte reserved |
| `$FF:0004` | FAULT_CAUSE | read | Bit 0 not present · 1 write to read-only · 2 execute from non-executable · 3 user access to supervisor page · 4 user access to bank `$FF` · 5 malformed PTE / walker error |
| `$FF:0006` | CONTEXT | read | ASID active at the time of the fault |
| `$FF:0008` | MODE | read | Bit 0 set if the fault occurred in user mode |
| `$FF:0010` | TLB_FLUSH_ASID | write | Invalidate every entry tagged with the ASID written. Other ASIDs untouched. Synchronous. |
| `$FF:0012` | TLB_FLUSH_ALL | write | Invalidate everything regardless of tag. For global kernel-mapping changes and bring-up — on a hot path it is a design smell. Synchronous. |
| `$FF:0014` | CTX_SET_ASID | write | Set the tag attached to new entries and matched on lookup. Does *not* flush. Synchronous. |
| `$FF:0016` | CTX_SET_PTBASE | write | SDRAM frame number the walker reads PTEs from. Write this **before** CTX_SET_ASID. Synchronous. |
| `$FF:0018` | CACHE_FLUSH_FRAME | write | Write back every dirty sub-block of the given 2 KB frame, then mark clean. Required before evicting a page to the card. **Asynchronous.** |
| `$FF:001A` | TLB_INVAL_PAGE | write | Invalidate one translation for the active ASID — the cheap path for single-page `munmap` and for permission downgrades such as marking a page read-only for copy-on-write. Synchronous. |
| `$FF:001C` | CACHE_FLUSH_ALL | write | Write back all dirty lines. Shutdown, suspend, bring-up. **Asynchronous.** |
| `$FF:001E` | MMU_STATUS | read | Bit 0 `BUSY` — an asynchronous command is running · bit 1 `WALK_ERR` — the walker met a malformed PTE · 15:2 reserved |
