# BIOS — what it provides
> residency · services · boundary with the EC

There's no BIOS chip: it's a binary on the SD that the RP2354B preloads into SRAM. The 65816 comes to life with the `$FFFC` vector pointing inside that zone.

- I.1 — Residency: `bios.bin` in the EC's flash → written into the pinned SRAM by the Debug Agent before the CPU leaves reset (step 5 of ![F.bootseq], [D82](sec_ai_q#d82)). No flash of its own, and nothing on the card.
  NOTE: This supersedes `BIOS.BIN` on the card, preloaded by the RP2354B: [D60](sec_ai_q#d60) moved it into EC flash and gave the card to Helium alone ([G.2](sec_ai_g#g2)).
- I.2 — At reset it provides: CPU init (native mode `CLC/XCE`, stack, direct page), MMU in supervisor identity mapping, cache init, quick memory test, UART console, and boot screen.
  NOTE: **The boot screen costs the BIOS nothing to produce.** Neon is already displaying when the first instruction runs — it does not have to be probed, put into a mode, or given a font — so `putchar` is a 16-bit `STA` to `$FE0000,x`, absolute-long indexed so the routine runs from any bank, and scrolling is one store to `TEXT_START` rather than 8 KB of block move ([T1.54](sec_ai_t1#t154), [T1.27](sec_ai_t1#t127)). The one sensible probe is reading `NEON_ID` for `$4E` once, purely to tell "no Neon fitted" from "Neon fitted", and continuing either way.
  NOTE: "Quick" is doing real work in that list: the BIOS is already fetching its own instructions out of the memory it would be testing, so it can only check what is not under it. The march test that has no such problem runs at [E2](sec_ai_p3#e2), before any CPU exists ([R.22](sec_ai_r#r22)).
- I.3 — Machine monitor: peek/poke, dumps, serial loading — the working tool for stages E2–E4.
  NOTE: A user button wired to Helium raises NMI, which is how you drop into the monitor on a machine that is already running rather than resetting it to get there.
- I.4 — OS loader: **reads the kernel image from the card's boot partition** — an MBR parse, a block read and the kernel's own loader, no filesystem — verifies its CRC, and jumps to it; the kernel finds the **info block** at its fixed address: RAM size, device map, battery state, and RTC time (via EC). A kernel pre-loaded into the staging area by the Debug Agent is booted instead, for bring-up ([CN1.4](sec_ai_cn1#cn14)–[CN1.6](sec_ai_cn1#cn16)). [[open]]
  NOTE: **This supersedes an NVFS reader in the BIOS** that mounted the volume read-only to find `KERNEL.BIN` ([D107](sec_ai_q#d107)): that reader would have had to follow every format change of [sheet Y2](sec_ai_y2). The rule it carried survives in the kernel's read-only mount — a read-only mounter must refuse a volume that is dirty or whose journal is non-empty ([Y2.20](sec_ai_y2#y220), [CN1.16](sec_ai_cn1#cn116)).
  NOTE: **On a failure the BIOS prints and halts, and never reboots in a loop**, since a loop erases the message ([CN1.4](sec_ai_cn1#cn14)).
  NOTE: The info block's `RTC time` field is currently unfulfillable: **no part of this board holds a wall clock**, which is why every timestamp the filesystem writes is zero ([Y1.17](sec_ai_y1#y117), [Q88](sec_ai_q#q88)).
  NOTE: Exact block format yet to be finalized (→ N).
  NOTE: **The block has a name, a home and an owner now, and it is the same block** ([D91](sec_ai_q#d91), [VM2.28](sec_ai_vm2#vm228)). It is the **system information block**: the last 2 KB page of bank `$00`, shared read-only, written here before paging is enabled and mapped identically into every process — so the kernel can read it after the handover instead of having it handed over once ([VM2.29](sec_ai_vm2#vm229)). It gains a format version, the CPU identity, Helium's capabilities and the resolved VM gate ([I.7](sec_ai_i#i7)) alongside the RAM size, device map and battery state already listed, and the text geometry the console reads ([CN1.4](sec_ai_cn1#cn14)). What remains open is the field-level encoding (→ [Q168](sec_ai_q#q168)).
- I.5 — Residual services to the OS: a small `JSL` jump table (putchar, getchar, read sector) during the transition; once the kernel drivers take over, the BIOS stops being used.
- I.6 — Boundary of responsibilities: the RP2354B is the "board BIOS" (everything pre-CPU); this binary is the "system BIOS" (everything post-reset). Together they cover what a single firmware does in a PC.
- I.7 — **The BIOS owns the CPU probe and the gate selection, and it owns them because it is the one place where both facts are available at once.** *Which CPU is executing* comes from the CPU itself, through a `WDM #WDM_CPUID` probe: on a real W65C816S `WDM` is a guaranteed two-byte no-op and A comes back unchanged, on Argon 2 it loads a non-zero signature, so **the probe cannot misreport** ([D89](sec_ai_q#d89), [NV1.12](sec_ai_nv1#nv112)). *What surrounds the CPU* comes from Helium's capability register ([M.16](sec_ai_m#m16)) — whether Argon carries an NVM32 core, the MMU version, the cache size — because **Helium cannot see electrically which CPU is on the bus, and the CPU cannot see what is around it.** The BIOS writes the resolved 24-bit gate vector into the block, and the kernel calls through it without knowing which machine it is on ([VM2.25](sec_ai_vm2#vm225), [VM2.26](sec_ai_vm2#vm226)).
  NOTE: **Helium writes nothing here, and that is a boundary rather than a detail.** It could — the Debug Agent already writes memory to load `bios.bin` ([D82](sec_ai_q#d82)) — but a gateware block that knows the software memory layout means moving a vector costs a bitstream. **Hardware supplies facts; software decides policy** ([VM2.27](sec_ai_vm2#vm227)).
  NOTE: All detection happens in one place, once, at boot. That is the property worth protecting as the block grows: the moment a second party probes for the same fact, the two can disagree.
- I.8 — **BIOS implementations may differ between machines; the block's format may not.** Reset, hardware initialisation and clocking are the parts that genuinely differ between a board with a physical W65C816S and one with Argon 2, and they are below this line. **What crosses the line is the block** — which is what lets **two BIOS implementations sit below one kernel** ([NV1.11](sec_ai_nv1#nv111), [D92](sec_ai_q#d92)). It therefore carries a version field from the first revision, not from the first incompatible change.
